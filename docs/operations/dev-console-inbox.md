# 개발자 문의 운영함

`/dev/inbox`는 플랫폼 운영자 전용 통합 문의 큐다. 저장소를 새로 복제하지 않고
각 원본을 읽으며, 원본별 처리 상태를 사용한다.

## 접근 권한

- 프런트와 API 모두 `OWNER_TENANT_ID` 테넌트의 활성 owner만 허용한다.
- superuser도 `OWNER_TENANT_ID`의 활성 멤버십이 있어야 한다.
- 일반 owner, teacher, student, parent와 다른 테넌트 요청은 거부한다.

## 유입 소스

| 화면 유형 | 원본 | 포함 조건 | 처리 완료 기준 |
|-----------|------|-----------|----------------|
| 도입 문의 | `LandingConsultRequest` | `OWNER_TENANT_ID`, `promo-contact` 또는 `promo-demo` | `resolved_at` 존재 |
| 버그/개선 | `PostEntity` | `support_kind`가 `bug`/`feedback`; 기존 `[BUG]`, `[FB]`, `[FEEDBACK]`도 읽기 호환 | `platform_staff` 답변 존재 |
| 빠른 문제 신고 | `OpsAuditLog` | `action=user_incident.manual` | `PlatformInboxIncidentState.status=resolved` |

신규 버그/개선 문의는 `POST /api/v1/community/support/`만 사용한다. 지원 티켓은
일반 게시판·관리자 커뮤니티 목록·공개 랜딩 조회에서 제외된다. 기존 제목 접두사
문의는 조회 호환만 유지하며 데이터 마이그레이션으로 수정하지 않는다.

## 운영 동작

- 목록은 유형, 처리 상태, 검색어, 페이지를 지원한다. 상단 집계는 현재 필터와
  무관한 전체 큐 기준이다.
- 도입 문의의 확인 시각(`read_at`)과 처리 완료 시각(`resolved_at`)은 분리한다.
  내부 메모는 원본의 `admin_memo`에 저장한다.
- 빠른 문제 신고 원문은 변경하지 않는다. 상태와 메모는 조회용 스냅샷에
  저장하면서 append-only `inbox.incident_status` 감사 로그도 함께 남긴다.
- 지원 티켓은 플랫폼 답변 등록 시 완료된다. 완료 후 문의자가 후속 답변을
  남기면 다시 미처리 상태가 된다. 문의·대화·첨부 기록은 제출 후 학원 측과
  플랫폼 운영자 모두 수정하거나 삭제할 수 없다.
- 문의 생성과 플랫폼 답변 등록은 각각 클라이언트 재시도 키로 멱등 처리한다.
  저장 후 응답만 유실돼도 동일 문의나 답변을 중복 생성하지 않는다.
- 첨부 업로드는 클라이언트 재시도 키를 사용한다. 서버 응답만 유실된 재시도는
  기존 첨부 메타데이터를 반환한다. 동일 게시물 업로드는 DB row lock으로
  직렬화하며 파일 내용 해시가 다른 키 재사용은 거부한다.
- 전화번호와 문의 내용은 플랫폼 운영자 화면에만 표시한다. 운영 알림에는 이름,
  전화번호, 본문을 포함하지 않는다.

## 운영 확인

1. `/dev/inbox`에서 전체·미처리 집계가 실제 목록과 맞는지 확인한다.
2. 도입 문의를 선택해 유입 경로와 연락처가 표시되는지 확인한다.
3. 테스트용 지원 티켓에 답변한 뒤 학원장/선생님 발신 화면에서 답변 본문이
   보이는지 확인한다.
4. 일반 커뮤니티 게시판과 공개 랜딩에서 지원 티켓이 노출되지 않는지 확인한다.
5. 운영 검증 중 실제 도입 문의의 상태나 메모는 변경하지 않는다.
