# V1.11.12 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-26 KST

**Scope:** Teacher-accurate promotion, immutable static Matchup previews,
narrow-mobile image containment, and full production closure

## 1. Decision

GO. The public HakwonPlus promotion now describes Matchup and classroom PPT
generation in the terms teachers actually use, proves both workflows with real
product output, and serves public Matchup previews as prepared JPEG derivatives
instead of rendering a PDF or waiting on a queue during each visit.

## 2. Delivered Behavior

- Matchup is presented as the evidence workflow that compares an academy's
  previously prepared material with a later school exam and shows how a similar
  problem appeared in the real test.
- PPT generation is presented separately as a classroom preparation workflow:
  split material by problem or concept, apply black/white inversion for a
  blackboard beam projector, build the PPT, and operate it with a remote.
- The promotion uses exact product screenshots and concise teacher-first copy;
  it does not imply that Matchup itself creates a PPT.
- Public report detail, share, showcase, and tenant landing paths use a native
  static image preview. The full PDF remains available through an explicit
  action.
- Public preview reads are cache-only. They never render a PDF or enqueue work
  in the browser request. A missing derivative returns a bounded retry response.
- JPEG preview keys are content-addressed and versioned. Publication prewarms
  the derivative before making the corresponding content public.
- Preview ETags are derived from the actual JPEG bytes. Conditional reads return
  `304 Not Modified`.
- Tenant 2 (`tchul`) has all three public Matchup reports prewarmed and serving
  cache hits.
- Mobile media keeps its native ratio. Hero and instructor fallback images no
  longer escape their containers, and contact cards fit narrow screens.

## 3. Compatibility and Data Safety

- No schema or data migration was required.
- Rendering is bounded to a 4096-pixel side and 12-megapixel output.
- Immutable derivative keys prevent an older concurrent render from
  overwriting newer public content.
- Heavy PDF rendering and object-storage I/O occur outside database locks.
  Publication uses a short optimistic comparison step before committing.
- Existing PDF download and authenticated report-generation behavior remains
  compatible.

## 4. Six-Lens Release Review

- **Functionality:** promotion copy and screenshots match the two real teacher
  workflows; every relevant public surface uses the same static preview model.
- **Security and privacy:** tenant resolution and existing public-visibility
  rules remain enforced; public reads expose only the prepared derivative.
- **Data and concurrency:** content-addressed keys, immutable writes, byte-level
  ETags, and optimistic publication prevent stale derivative races.
- **Operations and deployment:** backend image deployment, API/workers,
  Cloudflare Pages, production E2E, tenant availability, and canaries pass.
- **UX and accessibility:** preview images load immediately, keep their ratio,
  expose explicit PDF access, and remain contained on narrow mobile screens.
- **Regression and maintenance:** focused backend suites, smoke tests, boundary
  guards, frontend type/lint/build gates, and production browser checks pass.

Independent backend, frontend, and security audits reported no P0-P3 finding.
No release-scoped Critical or High finding remains.
