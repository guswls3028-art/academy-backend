# V1.11.1 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-26 KST

**Scope:** Student-specific Kakao Alimtalk final-send preview, canonical
provider-payload parity, accessible recipient selection, and controlled
production delivery proof

## 1. Decision

GO. Immediately before sending an Alimtalk, an operator now sees the complete
Kakao-style message using the same server-rendered values that are passed to
the provider. The operator can open the full student list, switch the preview
recipient, and identify excluded recipients before confirming the send.

The change is production-deployed and was verified through the browser,
application API, worker, queue, database delivery log, and provider receipt.
The only real recipient used for release verification was the fixed controlled
number `01031217466`.

## 2. Delivered Behavior

- The final confirmation presents the full approved Kakao envelope rather than
  only the teacher-entered memo.
- Student selection changes the preview only; the send target set remains
  explicit and is summarized independently.
- `전체 학생 열기` exposes a searchable, keyboard-operable recipient list with
  a clear selected state on desktop and mobile.
- Invalid or missing phone numbers are excluded from the valid-target count and
  display a reason instead of producing a misleading send preview.
- The backend returns each recipient's masked phone, exclusion state,
  `template_type`, and canonical `full_message_body`.
- Preview rendering reuses the production Solapi replacement contract,
  including academy/student/site values, missing-value fallback, and
  item-list truncation. Display-only full message text is stripped before the
  signed preview token is issued.
- The nested confirmation dialog traps and restores focus, closes with Escape,
  and supports Arrow/Home/End navigation across recipient radio options.
