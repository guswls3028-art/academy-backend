# V1.12.8 Release Notes

**Status:** Production-deployed / GO as a review-required Beta

**Release date:** 2026-07-29 KST

**Scope:** Scalable teacher tools hub and a privacy-bounded AI
problem-solution/explanation draft workflow

## 1. Decision

GO. Teachers can open the renewed tools hub at `/teacher/tools`, search and
filter registered tools, keep using the existing stopwatch, and open the new
AI problem solver at `/teacher/tools/problem-solver`.

The problem solver is intentionally a Beta and produces only a
teacher-review-required draft. It does not publish to students or write to
canonical problem, score, or curriculum data.

## 2. Product and Implementation

- Replace the single-purpose tools entry with a registry-driven hub that can
  grow without expanding the navigation drawer for every new tool.
- Add search and category filters while retaining the existing stopwatch.
- Add `Beta` labels on the problem-solver card, input page, and result page.
- Accept one JPG, PNG, or WebP problem image up to 12 MB, with a minimum short
  side of 320 px and a 40-megapixel decompression ceiling.
- Let teachers optionally select a subject before requesting a draft.
- Return a bounded answer, step-by-step explanation, answer-check rationale,
  confidence, and the fixed `teacher_review_required` status.
- Retry transient status-poll failures without turning them into a terminal
  job failure or enabling a duplicate submission.

## 3. Data and Safety Contract

- Require authenticated tenant-resolved staff access for create and status
  endpoints; student access is denied.
- Scope every job to the authenticated tenant and requesting user. Cross-user
  and cross-tenant status reads return not found.
- Require an explicit confirmation that the image contains no student name,
  contact information, or other personal data before upload.
- Keep the source under a tenant-prefixed temporary object key and delete it
  on API upload/dispatch failure and in the worker's terminal `finally` path.
- Remove the source object key from the terminal database payload.
- Remove the worker's local temporary directory on success and failure.
- Return only a public result whitelist, generic provider-independent errors,
  and `Cache-Control: no-store`.
- Preserve the existing AI quota, prompt-injection, queue visibility, and
  scale-to-zero worker boundaries.
- Add no migration and do not rewrite or delete user-authored rows.

## 6. Controlled Residuals

- A cold request can take roughly one to two minutes while the AI worker pool
  scales from zero. The UI keeps controls disabled and shows an explicit
  processing state during that interval.
- AI output can still be incomplete or wrong. The Beta never claims an
  approved answer and requires teacher review before classroom use.
- The broader teacher route migration remains a separate draft change and is
  not part of this release; the live canonical path remains `/teacher/tools`.
