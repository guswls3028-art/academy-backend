## 1. Decision

CONDITIONAL GO for the released production scope.

The affected student's authenticated production path returned HTTP 200 from the
playback API, HTTP 200 from the signed CDN master and variant playlists, and
HTTP 206 from a ranged media-segment request. The backend deployment workflow,
frontend deployment workflow, and post-deploy production canary all completed
successfully. The sole deployment-verifier warning is the local Wrangler R2
bucket-list probe, which lacks usable operator credentials in that shell; it is
not a playback-path or application-health failure.

## 2. Incident and Root Cause

Production `/academy/api/env` omitted `CDN_HLS_BASE_URL`,
`CDN_HLS_SIGNING_SECRET`, and `CDN_HLS_SIGNING_KEY_ID`. The API consequently
fell back to a private `r2.dev` URL and returned it unsigned. The playback API
looked successful while the issued media URL returned HTTP 401.

The first single-instance configuration refresh also briefly left the API
target group without a healthy target. Neither outage was an intentional
maintenance event.

## 3. Repairs

- Require production to use `https://cdn.hakwonplus.com`, a signing secret of
  at least 32 characters, and the explicit active signing key ID `v1`.
- Fail production startup, environment inspection, and SSM synchronization
  before serving traffic or replacing an instance when the signed-CDN contract
  is unsafe.
- Keep the signing secret masked even in verbose environment inspection.
- Validate video-worker HLS and thumbnail callbacks against the exact
  tenant/video object prefix.
- Run an isolated candidate API server against a non-production database and
  execute a real R2 -> signed CDN master -> variant -> ranged segment chain
  before any production runtime mutation.
- Block migrations and every production runtime update until the isolated
  pre-production canary succeeds.
- Preserve healthy API headroom during replacement, then return the ASG to its
  normal desired capacity.
- Refetch the playback API on student retry so a fresh signed URL is issued.
- Distinguish CDN authorization and service failures from student device or
  network failures in the player UI.
