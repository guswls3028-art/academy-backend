# V1.11.20 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-27 KST

**Scope:** Productized weekly wrong-note PDFs, per-question image persistence,
teacher-first CTA and responsive workflow, tenant-safe generation, and full
production closure

## 1. Decision

GO. A teacher can open a student's result drawer, review the wrong questions
from one exam or the full lecture history, and create a downloadable Korean PDF
from the same screen. Wrong questions are grouped by week and retain the
question image entered during answer-key registration. Missing-image questions
remain usable and clearly explain how to add the image.

## 2. Delivered Behavior

- Rebuilt the wrong-note area as a product workflow rather than a raw data
  list:
  - a paper-stack hero explains the outcome;
  - `이번 시험` and `강의 누적` scope controls make the collection boundary
    explicit;
  - weekly cards show exam, question, answer, explanation, and image state;
  - a persistent `오답노트 PDF 만들기` CTA becomes `PDF 다운로드` when ready.
- The cumulative scope selects the latest canonical result for each exam and
  groups wrong questions by lecture session/week. Append-only result facts are
  not treated as the current answer state.
- Answer-key registration now persists the problem image on the exam question.
  Explanation images remain a separate field. Teachers can explicitly change
  or delete an image without a stale server response restoring the deleted
  draft.
- Generated PDFs include a Korean cover, one question per page, problem image
  or a polished missing-image placeholder, the student's answer, the correct
  answer, score, and explanation.
- The same UI works at desktop and narrow drawer widths. Tabs expose correct
  tablist/tab/tabpanel semantics and Arrow, Home, and End keyboard behavior;
  load failures expose an alert and retry action.

## 3. Security, Isolation, and Lifecycle

- Wrong-note list, PDF create, and PDF status APIs are staff-only and require
  current-tenant membership. Generic question and explanation administration
  endpoints are also staff-only; the existing student exam-question API
  remains the student read path.
- Every enrollment, exam, result, question image, PDF job, and R2 object is
  tenant-bound. Storage keys must start with the current tenant prefix.
- PDF creation permits one active job per tenant, enforced with a tenant row
  lock. Stale pending/running jobs recover safely.
- Creation is limited to 10 requests per user per hour, at most 100 questions,
  and a 90-second generation deadline.
- Remote images use bounded reads and timeouts, with validated PNG/JPEG/WEBP
  content, a 10 MB byte limit, and a 20 megapixel decode limit. Images are
  processed sequentially and closed after use.
- Failed jobs do not expose a presigned URL. A failed object cleanup preserves
  the storage key for later recovery instead of falsely reporting deletion.
- Permanent student deletion locks the tenant, refuses deletion while a
  wrong-note PDF is active, and synchronously removes related R2 objects.
- The release adds no wrong-note database migration; it uses the existing
  `WrongNotePDF`, result, enrollment, exam, question, and image fields.
