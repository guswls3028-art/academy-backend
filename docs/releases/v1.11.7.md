# V1.11.7 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-26 KST

**Scope:** Promotion trust hardening through first-class privacy-consent
evidence, layout-stable real-product screenshots, and full production closure

## 1. Decision

GO. The V1.11.3 teacher-first promotion experience remains the public product
story, and its lead intake is now backed by a dedicated, auditable consent
contract instead of relying only on message text.

The production page continues to lead with the real exam-screenshot to matchup
to lesson-PPT flow requested by Daechi teachers. All promotion screenshots are
current product screens populated with the Gaepo High School demonstration
dataset; no generic mockup or invented performance claim was introduced.

## 2. Delivered Behavior

- Promotion demo and contact requests send `privacy_agreed: true` and
  `privacy_policy_version: "1.2"` as dedicated API fields.
- The backend records the consent flag, exact policy version, and server-side
  `privacy_agreed_at` timestamp on the consultation record.
- `promo-demo` and `promo-contact` requests fail closed when consent is
  missing, false, or uses a stale policy version.
- Existing non-promotion tenant landing forms remain backward compatible and
  are not forced onto the new promotion-only contract.
- The consultation-admin response exposes the three consent-evidence fields
  for operational review.
- Promotion product images and the brand mark now reserve their exact
  intrinsic dimensions. This prevents layout shift while preserving the real
  desktop, mobile, matchup, and PPT screenshots.
- The main journey, feature guide, parent-consultation guide, video guide,
  pricing, demo, contact, FAQ, and dedicated matchup-to-PPT page retain their
  route-specific metadata and teacher-oriented operating guidance.

## 3. Compatibility and Data Safety

- Migration `0047_landing_consult_privacy_consent` is additive only: one
  boolean, one policy-version string, and one nullable timestamp.
- The migration contains no destructive data operation and no historical-row
  rewrite.
- Enforcement is bounded to the two public promotion sources. Legacy landing
  requests continue to be accepted and store an empty consent version with no
  consent timestamp.
- Production verification did not submit a real consultation request, send an
  Alimtalk, or create a test lead. The form E2E intercepted the network request
  and asserted its payload locally in the browser.
