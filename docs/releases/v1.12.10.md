# V1.12.10 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-30 KST

**Scope:** Release-bound preproduction isolation, retry-safe image promotion,
single-tenant product-analytics pilot operations, and official mock-exam month
correction

## 1. Decision

GO. The production release path now keeps all immutable candidates away from
the compatibility `latest` aliases until persistent development, isolated
preproduction, production migration, rolling runtime replacement, and
post-deploy real-use verification have all passed.

Preproduction uses a release-bound SSM parameter version and a dedicated
database role that can connect to `academy_api_preprod` but is explicitly
denied `CONNECT` to the production database. Failed verification-job reruns
renew or conditionally reacquire the shared production mutation lock, and
promoting an already-current `latest` digest is an exactly read-back no-op.

Product usage analytics is enabled only for the `hakwonplus` pilot tenant.
All seven other tenant programs remain disabled. The pseudonymous actor HMAC
key is stored in the existing production SecureString, and daily rollup plus
30-day raw / 400-day daily retention maintenance is scheduled and has passed
one executed production run.

The student official mock-exam submission flow now accepts every month from
1 through 12 instead of forcing the historical June/September assumption.

## 2. Product and Implementation

- Publish the preproduction environment as an Advanced SecureString whose exact
  version and release ID are passed to the temporary canary.
- Replace inherited production DB credentials with the dedicated
  `academy_api_preprod_app` role before the canary starts.
- Verify current database/current user and deny the preproduction role access
  to the production database before health and CDN checks can pass.
- Build only immutable run-unique tags. Move all six `latest` aliases only
  after complete runtime verification, with exact digest readback.
- Require student playback credentials and the login, public-video discovery,
  signed master playlist, variant, and media-segment chain in production.
- Add a daily OIDC/SSM analytics maintenance workflow. Scheduled runs execute
  retention; manual runs default to dry-run unless explicitly set otherwise.
- Add an exact-confirmation, one-tenant platform API workflow for analytics
  enable/disable with login token masking and post-PATCH readback.
- Preserve an officially selected mock-exam month while switching year or
  score rows, expose months 1-12, and document that official months may change.

## 3. Data and Safety Contract

- Tenant resolution and analytics ingestion remain fail-closed. No default
  tenant or cross-tenant fallback was introduced.
- The pilot stores no raw account identifier. Actor identities are
  tenant-scoped HMAC hashes; event payload dimensions are registry-bounded.
- No user-authored, approved, score, message, file, or R2 object was deleted or
  rewritten.
- Immediate rollback for analytics is the same guarded single-tenant workflow
  with `enabled=false`; it stops new collection without deleting retained
  evidence.
- Preproduction migration uses only the dedicated database and role. Production
  mutation does not begin until the temporary canary passes and terminates.
- Root/master credentials were used only for explicitly authorized manual
  prerequisite convergence and safe readback. Ordinary CI and deployments
  continued to use GitHub OIDC; no credential value was printed or copied into
  source or reports.
