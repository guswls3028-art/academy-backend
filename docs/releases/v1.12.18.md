# V1.12.18 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-08-02 KST

**Scope:** Seven-day supplement and clinic arrival preparation, operational
dashboard and notification surfaces, actionable empty states, and production
verification

## 1. Decision

GO. Teachers can now prepare for supplement and clinic arrivals from one
seven-day operational view instead of maintaining a separate spreadsheet.
The dashboard shows what is due today, the next expected arrival, later dates,
and missing arrival times. The existing header notification surface exposes
tomorrow's arrivals and unresolved times without introducing a separate
reservation menu or a second source of truth.

The feature reuses the existing supplement attendance memo and clinic booking
records. It adds no schema migration, copies no tenant data, and does not
rewrite teacher-authored notes. The backend candidate passed persistent
development, isolated preproduction, production migration, health-gated
rolling replacement, exact-digest verification, and manifest promotion. The
frontend candidate passed isolated preview, protected production deployment,
all-tenant availability, authenticated round-trip checks, and direct
authenticated dashboard verification.

## 2. Seven-Day Arrival Contract

- `GET /api/v1/lectures/attendance/arrival-overview/` returns the tenant-local
  date range from today through today plus six days, with explicit
  `range_days: 7`, `range_end`, and `summary.upcoming` fields.
- Supplement arrivals come from unresolved supplement attendance records and
  preserve the teacher's existing memo as the operational note. Clinic
  arrivals come from booked clinic sessions. No new reservation table or
  duplicate write path is introduced.
- The result remains tenant-scoped and permission-gated. It does not infer a
  default tenant or cross-tenant fallback.
- Missing-time counts cover the whole seven-day range rather than only today
  and tomorrow, so preparation gaps remain visible before they become urgent.
- The service retains a two-query budget for the complete overview, avoiding a
  per-day or per-student query loop as the preparation range expands.

## 3. Operational User Experience

- The dashboard presents today's arrivals, a compact next-arrival summary, and
  date-grouped later arrivals. The right-side preparation list is bounded to
  eight items so it stays scannable on ordinary and narrow screens.
- Summary chips are shown only for meaningful non-zero counts. When the range
  is empty, teachers see a compact explanation and direct actions for
  `강의에서 보강 입력` and `클리닉 예약 보기` instead of decorative zeroes.
- The header notification panel includes tomorrow's arrival preparation and
  `시간 미정 등원` when either is actionable. The teacher notification page
  routes the same arrival signals back to the dashboard preparation board.
- The populated, empty, and mobile layouts share the existing dashboard visual
  language. This makes the feature read as a natural upgrade to attendance,
  clinic, dashboard, and notification behavior rather than a new isolated
  subsystem.
