# V1.11.37 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-28 KST

**Scope:** HakwonPlus owner root-routing incident closure, explicit
developer-console boundary preservation, and production verification

## 1. Decision

GO for the released frontend scope.

The deployed HakwonPlus owner session now resolves the primary root to
`/admin/dashboard` on `hakwonplus.com`. Automatic role routing cannot enter the
developer console, while explicit `/dev` and `/dev/*` requests continue to
cross to the isolated `dev.hakwonplus.com` origin.

## 2. Incident and Root Cause

`RootRedirect` contained a legacy special case that sent the `hakwonplus` and
local `9999` owner roles to `/dev/dashboard`. After the developer console was
isolated on its own origin, the primary-origin `/dev/*` boundary correctly
forwarded that automatic route to `dev.hakwonplus.com`; the separate-origin
authentication boundary then displayed the developer login page.

## 3. Repairs

- Remove the legacy owner-only automatic `/dev/dashboard` branch.
- Route anonymous, admin-role, student, and parent root destinations through
  one executable resolver.
- Preserve desktop owner routing to `/admin`, the existing mobile
  `/teacher` preference, and student/parent routing to `/student`.
- Keep explicit primary-origin `/dev` and `/dev/*` requests isolated on
  `https://dev.hakwonplus.com`, including query strings and fragments.
- Add executable role, mobile, explicit-dev, and `RootRedirect` source-boundary
  contracts to prevent recurrence or helper bypass.
