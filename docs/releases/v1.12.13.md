# V1.12.13 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-08-01 KST

**Scope:** Teacher grading and attendance safety, configurable homework scoring,
regular/supplement result separation, deployment hardening, and expanded CI
coverage

## 1. Decision

GO. The backend and frontend changes through the commits recorded below are
deployed in production. The immutable backend candidate passed the persistent
development runtime, isolated preproduction, production migration, health-gated
runtime replacement, exact-digest, worker, queue, Video Batch, and final
verification gates. The frontend candidate passed its Cloudflare preview,
production deployment, tenant-availability, login, and teacher/student
round-trip gates.

## 2. Product and Implementation

- Added teacher-facing video playback controls to the free-review workflow.
- Made blank attendance explicitly `UNSET`, kept absence out of ranking, and
  added atomic bulk-present changes with a bounded undo path.
- Added per-homework maximum scores and kept score entry and result rendering
  aligned with that configured maximum.
- Separated regular-session and supplement-session performance scopes in the
  result console so teachers can review the intended population without mixing
  unrelated sessions.
- Added Korean/English input-language grading shortcuts, grading recovery
  guidance, and safer manual grading entry points.
- Added score Alimtalk preview and tolerant SpreadsheetML workbook intake while
  preserving the approved-message and explicit-review boundaries.
- Kept student, enrollment, score, attendance, and message writes tenant-bound
  and fail-closed throughout the new paths.

## 3. Delivery and Safety Hardening

- Made result-scope classification fail closed when the owning session context
  is absent or ambiguous.
- Added production-environment OIDC trust coverage and strengthened immutable
  image promotion and exact runtime verification.
- Added ECR critical-vulnerability gates with exact, expiring exception records;
  a new or mismatched finding still blocks the release.
- Hardened concurrent Codex session lifecycle and cleanup contracts so only an
  isolated, clean release-owner worktree can publish.
- Expanded the backend pull-request gate to the full Django suite with an
  enforced coverage threshold, and expanded the frontend mock gate to every
  owned Playwright mock specification.

## 4. Data and Migration Contract

- The attendance-state migration was applied by the production migration gate.
  Existing teacher-authored scores, attendance decisions, homework results,
  student links, and message history were preserved.
- Runtime rollout used the repository's expand/contract-compatible migration
  sequence while old and new API instances overlapped.
- The release-seal documentation itself introduces no schema or runtime change.
