# V1.11.29 Release Notes

**Status:** Production-deployed / GO with one-time iPhone re-enrollment

**Release date:** 2026-07-28 KST

**Scope:** Isolated developer-console origin, canonical install identity,
production API access, and iPhone Home Screen notification readiness

## 1. Decision

GO. The developer console now has the dedicated canonical origin
`https://dev.hakwonplus.com`. This separates its iOS Home Screen identity,
service worker, notification subscription, storage, manifest, and icon from the
public HakwonPlus application.

The former `https://hakwonplus.com/dev/*` paths permanently redirect to the
same path and query on the new origin. The new origin routes `/` to
`/dev/inbox`, serves the HakwonPlus console manifest and icons, and remains
excluded from search indexing.

## 2. Delivered Behavior

- `dev.hakwonplus.com` is bound to the production Cloudflare Pages project
  through an idempotent custom-domain and DNS lifecycle.
- The deployment resolves the project's actual Cloudflare `subdomain` instead
  of assuming that the project name equals its `pages.dev` hostname.
- A stale pending domain association is recovered only after 15 minutes, and
  either an active Cloudflare status or a successful HTTPS response proves
  readiness.
- `hakwonplus.com/dev` and all descendant paths issue a 308 redirect to the
  isolated origin while preserving path and query.
- The developer manifest uses `/dev/inbox` for `id` and `start_url`, `/` for
  scope, standalone display, and versioned HakwonPlus 192/512 icons.
- The service worker uses a developer-only app shell and offline fallback on
  the isolated origin. Notification clicks cannot escape the current origin.
- The developer hostname resolves to tenant code `hakwonplus`, so API requests
  retain the existing tenant header and platform-admin authorization boundary.
- The backend CORS and CSRF allowlists include only the exact new HTTPS origin.
- Teacher and student manifests remain tenant-specific; non-HakwonPlus tenants
  do not inherit HakwonPlus artwork.

## 3. Compatibility and Data

- Existing inquiry, support-ticket, incident, reply, attachment, push-outbox,
  and push-subscription data was not changed or copied.
- No model or database migration was required.
- Authentication storage is origin-scoped, so the operator signs in once on
  the new origin.
- Existing teacher/student PWA origins, manifests, icons, and push scopes are
  unchanged.
- The old installed iPhone icon must be removed and re-added from the new
  origin; notification permission and subscription are device-owned and cannot
  be transferred by deployment.

## 5. Audit Closure

The release was reviewed across backend/API contracts, tenant isolation,
frontend routing and state, destructive and boundary cases, iPhone install UX,
and security.

- No model, view, query, or permission code changed; platform-admin-only inbox
  and push authorization remain intact.
- The new hostname maps deterministically to the HakwonPlus tenant, and the API
  allows an exact origin rather than a wildcard.
- Cross-origin redirects preserve only the requested path/query, while
  notification destinations remain clamped to their own origin.
- Search indexing is blocked by both HTML and HTTP headers.
- Domain provisioning is idempotent and uses the Cloudflare project response
  as source of truth, avoiding cross-account CNAME assumptions.
- No user-created row was updated or deleted.

Critical findings: 0. High findings: 0. No release-scoped blocker remains.

## 6. Known Unrelated Gate

pre-existing `E2E_STUDENT_*` repository secret no longer matches the controlled
student account. API health, public promo, and admin login canaries passed
(3/4), and the Cloudflare deployment job and release-specific production
checks passed. This credential-maintenance issue predates and is independent of
the developer-origin change; it was not hidden or converted into a skip.

## 7. Device Activation

On the operator iPhone:

1. Delete the old Home Screen developer-console icon.
2. Open `https://dev.hakwonplus.com` in Safari and sign in once.
3. Use **공유 → 홈 화면에 추가**.
4. Open the installed **학원플러스 콘솔** and press **알림 켜기**.
5. Allow notifications in the iPhone permission prompt.
