# V1.12.9 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-30 KST

**Scope:** Fail-closed first-login guidance, public product updates, and
zero-downtime migration release enforcement

## 1. Decision

GO. Newly created owner, administrator, teacher, staff, student, and parent
accounts receive one role-aware first-login guide after any mandatory password
change. Existing accounts are marked complete by migration and are not
interrupted.

The public `/promo/updates` page exposes only available or explicitly bounded
features. The page is reachable from desktop/mobile promotion navigation and
the footer, and its Cloudflare edge route, metadata, canonical URL, and dynamic
sitemap are now part of the production deployment gate.

## 2. Product and Implementation

- Add nullable `User.first_login_guide_completed_at` and backfill all existing
  users as complete.
- Expose `first_login_guide_required` through the authenticated current-user
  response only when the current tenant membership is active.
- Add an authenticated, tenant-member-only, account-scoped and idempotent
  completion endpoint. It accepts no arbitrary user identifier.
- Keep mandatory password change ahead of the guide, provide role-specific
  next-step CTAs, and preserve retryable failure behavior when completion
  cannot be saved.
- Publish an accessible and responsive product-update timeline without
  presenting disabled product analytics as released behavior.
- Add a fail-closed expand/contract migration guard before image build.
  Automatic pushes reject contract operations; a separately annotated manual
  release is required after its expand release is fully deployed.
- Align durable deployment documentation with the executable persistent
  development, isolated preproduction, and health-gated production sequence.

## 3. Data and Safety Contract

- Tenant resolution remains fail-closed and no default or cross-tenant
  fallback was added.
- First-login completion mutates only the authenticated account and is
  idempotent.
- Existing accounts are preserved by the migration backfill; no
  user-authored, approved, score, message, or object-store data is rewritten.
- Migration `0052_user_first_login_guide_completed_at` is an expand-safe
  nullable addition followed by an existing-account data update.
- Public updates contain no private operational payloads or disabled
  analytics claims.
- Non-local first-login E2E refuses account mutation.
