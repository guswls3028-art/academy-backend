# V1.11.21 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-27 KST

**Scope:** Ambiguity-safe Excel exam-result imports, explicit attendance
confirmation for fully blank answer rows, and full production closure

## 1. Decision

GO. A row whose entire question area is blank is no longer interpreted
silently as a perfect score. Because the same blank cells historically meant
"correct," the importer now requires the operator to confirm whether that
student attended or was absent before any result can be applied.

## 2. Delivered Behavior

- The generated workbook uses an `응시 여부` column with `응시` and `결시`
  choices.
- A fully blank question row without either choice receives a blocking
  `attendance_confirmation` preview error. The apply action remains
  unavailable until the row is resolved.
- `응시` plus a fully blank question row is an intentional perfect score.
- `결시` continues to store the canonical
  `ExamAttempt.meta.status=NOT_SUBMITTED`, remains excluded from score and
  statistical denominators, and contributes to cumulative absence shading.
- A row containing at least one `O` or `X` remains a normal attended result, so
  existing workbooks with actual marks remain compatible.
- For an older workbook without the new column, an intentional perfect score
  can be confirmed by marking one correct question `O`.
- The workbook score helper displays `확인 필요` and highlights the attendance
  cell when a fully blank row still needs a choice.

Previously imported absence rows that were mistakenly stored as perfect scores
cannot be inferred retroactively. They should be re-imported once with `결시`
selected in the new workbook.

## 3. Data and Compatibility

- No database migration or infrastructure change was required.
- The import still resolves students by tenant-bound enrollment ID first and
  otherwise only within the exam roster.
- The preview and apply paths use the same parser contract; unresolved rows
  cannot bypass preview by submitting directly with `apply=true`.
- Existing `결시` header aliases and markers remain accepted.

The release-scoped source was reviewed through backend-domain, tenant
isolation, frontend integration, destructive-edge, UX/accessibility, and
security lenses.

- Domain: the ambiguity check runs before result planning or persistence;
  explicit attendance and absence preserve the established scoring contract.
- Tenant isolation: no route, permission, model, or cross-tenant query boundary
  changed; existing exam and enrollment tenant scopes remain in force.
- Frontend integration: the existing preview error contract drives both the
  visible row warning and omission of the apply action.
- Edge cases: fully blank unresolved, fully blank explicit attendance,
  explicit absence, and marked legacy rows are covered.
- UX/accessibility: the workbook has a visible helper state and the web preview
  provides readable blocking guidance on desktop and mobile.
- Security: no new authentication, secret, executable spreadsheet input, or
  persistence surface was introduced; existing formula-like student-text
  escaping remains covered.
