# V1.11.16 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-26 KST

**Scope:** Visual academy operations dashboard, explicit Alimtalk
responsibility boundaries, detailed feature workflows, and frontend production
closure

## 1. Decision

GO. The HakwonPlus administrator home now presents today's academy operation
as a calm visual board instead of a loose collection of shortcuts. The public
promotion explains, for every major function, what the system records or
automates, what the teacher confirms, and what the student or parent receives.
The Alimtalk guide distinguishes automatic, configured automatic, and direct
teacher-confirmed sends without claiming unsupported test-send behavior.

## 2. Delivered Behavior

- Rebuilt the administrator dashboard around four existing operational
  signals: active lectures, active exams, today's submissions, and unanswered
  questions.
- Added a prioritized work board for QnA, submission grading, active exams, and
  clinic passcard preparation, plus a compact explanation of how teaching
  records lead into follow-up communication.
- Added a dedicated Alimtalk status card with explicit loading, unavailable,
  disconnected, and ready states. A failed status request can no longer appear
  as ready.
- Kept all dashboard actions on existing routes and the existing clinic modal.
  No new query, mutation, metric, or backend endpoint was introduced.
- Replaced the generic promotion-strength cards with responsibility workflows
  for student video, Alimtalk, material production, and the academy homepage.
- Added the same four-stage explanation to lecture and student management,
  exams and scores, video, communication, homepage publishing, clinic,
  Matchup/PPT production, and parent consultation records.
- Divided Alimtalk behavior into:
  - account notices that are sent with the account operation;
  - clinic and answer notices that are sent automatically only when an approved
    template and academy setting are ready; and
  - attendance, score, class-result, and assignment notices that teachers
    review and send directly by default.
- Shows the recipient and excluded-recipient check, student-specific final
  copy preview, Kakao receiving form, and post-send history as separate steps.
  Common wording promises only the behavior shared by the supported send
  paths: the teacher reviews the target and final copy, then checks actual
  success or failure in message history.
- States transparently that a separate "send a test to my own number" function
  is not currently provided.
- Replaced the promotion's administrator-home image with a privacy-safe static
  screenshot of the redesigned real product screen. Visitors receive one
  prepared image and do not wait for live product data to render.

## 3. Compatibility and Data Safety

- No backend application code, database schema, infrastructure, API contract,
  migration, authentication, authorization, or tenant-resolution behavior
  changed.
- Dashboard data remains read-only and uses the existing lecture, exam,
  submission, QnA, and messaging-info contracts.
- Production E2E used Tenant 1 only for read-only dashboard inspection. It did
  not create, edit, delete, or send academy data or Alimtalk messages.
- The prepared dashboard image contains no student name, phone number, email
  address, or PNG text/EXIF metadata.
- Pricing, the continuing August signup price, grading scope, Matchup meaning,
  and classroom PPT workflow remain unchanged.

## 4. Six-Lens Release Review

- **Backend domain:** Alimtalk classifications and feature explanations were
  checked against messaging policy and current product paths.
- **Tenant isolation:** no tenant-scoped read or write boundary changed; the
  dashboard only reorganizes existing current-tenant queries.
- **Frontend integration:** routes, query keys, fetchers, modal entrypoints,
  anchors, static images, and responsive layouts remain internally consistent.
- **Destructive and security:** no production mutation, external HTML
  injection, new credential surface, or sensitive screenshot data was added.
- **UX and accessibility:** 1440-pixel and 390-pixel inspection found no broken
  image or horizontal overflow; native buttons, visible keyboard focus,
  reduced-motion behavior, and left-side scrollable mobile navigation remain
  intact.
- **Regression and operations:** typecheck, full lint, safety guards,
  production build, bundle budget, local promotion E2E, Cloudflare deployment,
  production promotion E2E, production dashboard E2E, round-trip flows, and
  tenant availability pass.

Three independent release audits ended GO with no remaining Critical or High
finding. Two High findings were closed before deployment: common Alimtalk copy
was narrowed so it did not promise one modal's checkbox and result counters on
every send path, and the dashboard messaging status stopped interpreting
loading or request failure as ready.
