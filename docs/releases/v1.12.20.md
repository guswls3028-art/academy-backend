# V1.12.20 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-08-02 KST

**Scope:** Per-homework cutlines, regular/supplement student score scopes,
protected frontend rollback closure, and production verification

## 1. Decision

GO. Homework created inside one lecture session can now use a different
cutline mode, value, and percent-rounding rule from its neighboring homework.
Existing homework without an override keeps the prior session policy as a
backward-compatible fallback, so the rollout does not reinterpret saved
teacher data.

The student detail `개인 시험 점수 모음` now separates all, regular-session,
and supplement-session exams. The selected scope changes the trend and exam
list together and keeps unclassified legacy records visible only in the full
view with an explicit `구분 필요` badge.

## 2. Per-Homework Cutline Contract

- `Homework.cutline_mode`, `cutline_value`, and `round_unit_percent` are
  nullable overrides. The existing `HomeworkPolicy` remains the default for
  older or intentionally unconfigured homework.
- Effective API fields expose the resolved mode, value, and rounding unit plus
  whether the session default is in use. Old API instances can overlap the
  additive migration without reading the new columns.
- Bulk creation accepts a distinct cutline for every row. The selected
  homework setup edits only that homework instead of changing all homework in
  the session.
- Template creation, template import, session copy, and homework copy preserve
  the override. Maximum-score and count-cutline validation use the same
  homework's effective values, including simultaneous mode/max-score edits.
- A homework override recalculates only that homework's first-attempt score
  snapshots and clinic links. A session-policy edit recalculates only homework
  that still inherits the default.

## 3. Student Score Scope Contract

- Student detail offers `전체`, `정규 수업`, and `보강` as one accessible
  tablist above the personal exam trend.
- Each scope shows its live count and filters both the chart and the exam list
  from the same in-memory response. It adds no API request or backend schema.
- Every exam row identifies `정규`, `보강`, or `구분 필요`, so the current
  filter has a visible data basis.
- ArrowLeft, ArrowRight, Home, and End move selection and focus together.
  The responsive layout was covered at desktop, compact desktop, and 390px.
