# V1.11.4 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-26 KST

**Scope:** Safe score-entry editing with automatic persistence, Excel-style
shortcuts, explicit save-and-lock completion, and concurrent-editor fencing

## 1. Decision

GO. The admin session score screen is locked by default, becomes editable only
after the operator selects `수정`, persists confirmed changes while the
operator works, and returns to a protected state through `저장하고 잠금`.

The workflow keeps the original mistake-prevention intent of edit mode without
requiring repeated mode toggles during entry. A later correction starts by
selecting `수정` again.

## 2. Delivered Behavior

- Confirmed score cells autosave after a 900 ms idle interval. Multi-digit
  typing does not send an intermediate partial value.
- `Ctrl+S` saves immediately, while `Ctrl+Z` and redo restore recent cell
  changes using familiar spreadsheet behavior.
- `저장하고 잠금` commits the active cell, flushes pending score requests,
  releases the edit lease, and returns the screen to read-only protection.
- Pending changes are preserved across SPA tab or session navigation. If the
  server draft request fails, recovery is scoped to the current browser tab.
- Recovery is fail-closed: send, OMR, export, print, and destructive discard
  actions stay blocked until the pending score state is safely resolved.
- Duplicate tabs receive distinct editor identities. A 409 server lease
  conflict takes precedence over local recovery so a stale tab cannot write.
- Score drawers and the shared exam result panel no longer provide alternate
  mutation paths outside the session score edit workflow.

## 3. Concurrency and Compatibility

- A two-minute score edit lease identifies the tenant, session, user, and
  browser editor. Heartbeats keep an active editor's lease current.
- Exam total, objective, subjective, item, and homework score mutations require
  the matching active lease.
- Session row locks are held in the same database transaction as the score
  mutation, preventing a stale writer from passing validation and committing
  after another editor takes over.
- The browser headers `X-Score-Editor-Client` and `X-Score-Session-Id` are
  explicitly allowed by both base and production CORS settings.
- Existing score draft payloads remain readable. The feature adds no database
  migration.
