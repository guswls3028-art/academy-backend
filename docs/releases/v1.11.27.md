# V1.11.27 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-28 KST

**Scope:** Attendance-roster result-detail parity and restored wrong-note entry
from session score tables

## 1. Decision

GO for opening an exam result and creating a wrong-note PDF from a student who
appears in a session score table through the attendance roster.

The score-table roster and the result-detail authorization now recognize the
same tenant-safe student population. A teacher can click a visible score,
inspect the student's per-question result, and enter the existing wrong-note
workflow without receiving the previous HTTP 400 response.

## 2. Delivered Behavior

- A same-tenant active attendance record can establish result-detail access
  when the student has not yet been materialized as a session enrollment.
- The attendance, session, exam, and student enrollment must all belong to
  the same lecture; a contaminated cross-lecture attendance row grants no
  access and does not appear in the effective score roster.
- Existing exam-enrollment and session-enrollment paths remain unchanged.
- An unrelated student still receives the existing HTTP 400 boundary.
- Existing score-write behavior can materialize the exam enrollment after a
  legitimate session-roster match.
- No schema or data migration is required.

## 3. Teacher Workflow

1. Open a lecture session and select **성적**.
2. Select an exam and click the student's score cell.
3. In **답안 상세**, select **오답노트 만들기**.
4. Choose the current exam or accumulated lecture scope and create the PDF.

Question images already registered with the exam are reused by the wrong-note
generator.

## 5. Production Evidence and Boundary

The signed-in production session reproduced the original failure shape:
a student visible through the score-table roster received HTTP 400 when
opening result detail. After deployment, the target test enrollment and result
records had been removed by concurrent test-data cleanup, and the same session
therefore displayed zero students.

No synthetic production student, score, or result was created to fabricate a
click-through proof. The repaired path is covered by attendance-only
read/write regression tests and by the successful production deployment and
canary evidence above.
