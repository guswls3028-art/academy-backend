# V1.11.23 Release Notes

**Status:** Production-deployed / GO with device notification activation

**Release date:** 2026-07-27 KST

**Scope:** Real-use developer inbox, durable iPhone web-push alerts,
tenant-specific installed-app branding, and agent-monitor removal

## 1. Decision

GO. The developer inbox now renders production inquiry, support-ticket, and
incident data through one operational queue with reply, status, attachment,
search, filter, and pagination workflows. The unused agent activity viewer was
removed from the navigation, routes, components, and bundle.

The developer console can be installed from iPhone Safari as a Home Screen web
app and can receive inquiry/bug notification banners after the operator presses
`알림 켜기` and grants permission. Teacher and student Home Screen apps derive
their icon and display name from the active tenant; a non-HakwonPlus tenant
never falls back to the HakwonPlus logo.

## 2. Delivered Behavior

- `/dev/inbox` combines landing consultations, support tickets, and operational
  incidents while preserving each source's reply and lifecycle semantics.
- Platform-admin-only APIs expose inbox detail, reply, status, attachment, and
  push-subscription operations.
- Idempotency, server-side search/filtering, bounded pagination, attachment
  validation, and explicit empty/error/loading states support daily operation.
- `PlatformPushOutbox` persists notification work with deduplication,
  coalescing, bounded retries, exponential backoff, and stale-lock recovery.
- The five-minute operations workflow dispatches due push events before
  evaluating incident rules; manual dry-run and SMS-test modes never dispatch
  platform push.
- Push subscriptions are split by `platform` and `teacher` scope and platform
  subscriptions require an active platform owner/superuser.
- Push endpoints are restricted to the supported Apple, Google, and Mozilla
  HTTPS hosts, and notification payloads contain no customer PII.
- Root, teacher, and student service workers clamp notification destinations to
  the current origin and only manage their own caches and client scopes.
- The developer app uses HakwonPlus artwork. Known tenant apps use exact tenant
  assets, while new or unknown tenant domains use uploaded tenant branding or a
  neutral non-HakwonPlus fallback.
- Teacher and student routes select their dedicated dynamic manifest before the
  SPA loads. The developer route selects `/dev-manifest.json`.
- The agent-monitor route, page, components, API client, store, tests, and
  navigation entry were removed.

## 3. Data and Compatibility

- Core migration `0050_platformpushoutbox` adds the durable platform
  notification queue.
- Teacher-app migration `0002_pushsubscription_app_scope` separates platform
  and teacher subscriptions without invalidating existing teacher devices.
- Existing teacher push behavior remains scoped to teacher subscriptions.
- Existing inquiry/support/incident records remain in their source tables; the
  developer inbox is a unified operational projection rather than a destructive
  data migration.
- VAPID credentials are stored in the encrypted production runtime parameter;
  no key material is committed to source control.

## 6. Audit Closure

The release was reviewed across authorization, tenant isolation, transaction
boundaries, retry behavior, SSRF exposure, notification privacy, service-worker
scope, cache ownership, install branding, and deployment race handling.

- Request threads only enqueue durable work; external push delivery happens
  outside the request transaction.
- Duplicate signals coalesce, failed deliveries retry within explicit bounds,
  and invalid/expired subscriptions deactivate safely.
- Platform subscriptions cannot be created through teacher permissions.
- Non-HakwonPlus domains cannot inherit HakwonPlus install artwork.
- A delayed AI container start is retried only for the exact not-yet-present
  condition; digest mismatches and other deployment failures still fail
  immediately.

Critical findings: 0. High findings: 0. No code, migration, runtime, or deploy
blocker remains.

## 7. Device Activation

Web Push permission is device-owned and cannot be granted during deployment.
On the operator iPhone, open `https://hakwonplus.com/dev/inbox` in Safari, use
`공유 → 홈 화면에 추가`, launch the installed `학원플러스 콘솔`, press
`알림 켜기`, and allow notifications. Registration is per installed device.
