# V1.12.15 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-08-01 KST

**Scope:** React Router advisory closure, React 19 compatibility migration,
arrival operations, preproduction readback reliability, and full production
continuity verification

## 1. Decision

GO. The frontend dependency graph no longer contains the React Router version
reported by `GHSA-qwww-vcr4-c8h2`, and the production audit is a blocking CI
gate. The arrival-planning backend and frontend are deployed with their
expand-only migration, tenant-scoped API, supplement-only edit boundary,
dashboard timeline, and alerts. The backend candidate passed persistent
development, isolated preproduction, production migration, health-gated API
and worker rollout, exact-digest verification, and manifest promotion. The
frontend candidate passed preview, protected production approval, login,
tenant availability, and teacher/student real-use gates.

## 2. React Router Security Closure

- Closed [GHSA-qwww-vcr4-c8h2](https://github.com/advisories/GHSA-qwww-vcr4-c8h2)
  without an audit ignore, package override, or vulnerable-version pin.
- The advisory affects `react-router` `>=7.12.0 <8.3.0`; production now uses
  exact `react-router` 8.3.0 with `react` and `react-dom` 19.2.7.
- Reverified current source as a declarative `BrowserRouter` SPA. It has no RSC
  entrypoint, `@react-router/dev`, server action, `createRequestHandler`,
  `HydratedRouter`, `RSCRouter`, or `react-server` boundary.
- Removed `react-router-dom`, migrated declarative imports to `react-router`,
  declared Node.js `>=22.22.0`, removed the obsolete Vite chunk boundary, and
  regenerated the lockfile.
- Added blocking `pnpm audit --prod` execution and a governance guard that
  rejects removal of the audit gate.

## 3. Arrival Operations

- Added the tenant-scoped
  `GET /api/v1/lectures/attendance/arrival-overview/` endpoint for today's and
  tomorrow's supplement and clinic arrivals, including soon, unset-time, and
  overdue summaries. The selector uses two domain queries and reaches clinic
  data only through `apps/support/attendance/arrival_dependencies.py`.
- Added nullable `Attendance.planned_arrival_date` and
  `Attendance.planned_arrival_time` through expand-only migration
  `apps/domains/attendance/migrations/0005_planned_arrival.py`. No constraint,
  index, destructive operation, or old-row rewrite is included.
- Planned fields are accepted only for `SUPPLEMENT` sessions; a time cannot be
  stored without a date. `Attendance.memo` remains the preparation memo and
  the plan stays independent from the actual attendance status.
- Added the supplement-only arrival editor, dashboard next-arrival timeline,
  today/tomorrow/soon/unset/overdue summaries, desktop and teacher-mobile
  alerts, and natural deep links to supplement attendance or clinic operations.
  Regular attendance sheets do not expose the arrival column.

## 4. Preproduction Reliability Closure

- The first arrival deployment run stopped before candidate preproduction at
  the exact-version SSM readback. Read-only metadata confirmed that version 30
  was created at the failure timestamp and became readable by its immutable
  selector, isolating the cause to short read-after-write propagation delay.
- The publisher now retries only `${PreprodEnvParameter}:$version` six times at
  two-second intervals. It still throws after the bounded window, and no
  production migration or runtime mutation can begin without a matching
  release ID, database boundary, credentials, settings module, and R2 boundary.
- The replacement production run proved the fix in the real workflow: exact
  environment publication, isolated instance migration and health checks, CDN
  chain, and instance termination all passed before production migration.
