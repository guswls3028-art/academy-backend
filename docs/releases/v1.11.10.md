# V1.11.10 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-26 KST

**Scope:** Shared-exam score-edit fencing, stale-draft recovery, teacher score
path convergence, and full production closure

## 1. Decision

GO. The V1.11.4 score-entry workflow remains locked by default, opens through
`수정`, saves confirmed cells continuously, supports `Ctrl+S` and undo/redo,
and closes through `저장하고 잠금`.

This release closes the concurrency and recovery gaps found during the
post-release six-lens audit. No release-scoped Critical or High finding remains.

## 2. Delivered Behavior

- A regular exam shared by multiple sessions now has one deterministic edit
  scope. An editor in any linked session blocks stale writes from another
  linked session.
- Automatic grading remains authoritative without losing manual input. It
  invalidates an active manual lease, preserves the draft, and requires an
  explicit recovery acknowledgement before that draft can write again.
- Duplicate tabs use document-lifetime editor identities. A copied
  `sessionStorage` value can no longer make two tabs the same lease owner.
- Recovery drafts are not released when a user navigates away while the
  recovery decision is still open. The recovery dialog traps focus, blocks
  racing actions, and restores focus after resolution.
- OMR upload stays disabled while editing, saving, recovering, or handling a
  save error. A failed lease release exposes a dedicated `잠금 다시 시도`
  action.
- Decimal scores retain up to two decimal places in editable and locked views.
- Teacher mobile score entry uses the same one-operation lease contract as the
  admin score screen. The teacher exam detail screen is read-only and routes
  score changes to the session score-entry surface.

## 3. Server Safety and Compatibility

- Excel result import and representative-attempt changes fail closed while a
  related manual editor owns an active lease.
- Automatic submission grading fences stale manual writers across every
  session linked to the exam.
- Result-detail GET is now a side-effect-free read. It neither creates a zero
  result/attempt nor materializes an exam assignment.
- Stale drafts cannot be cleared by a heartbeat, autosave commit, or a
  duplicated tab. Explicit restore/discard remains available.
- Existing draft payloads remain readable. No database migration was required.
- The production image also contains the already-merged incident-SMS,
  subscription-transition, and bounded AWS credential-setup hardening that
  followed V1.11.7.
