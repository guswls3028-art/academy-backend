# V1.11.19 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-27 KST

**Scope:** Selectable initial-password policies for Excel student imports,
encrypted credential recovery, forced first-login password change, and full
production closure

## 1. Decision

GO. Administrators and teachers can now choose how initial passwords are
created during Excel student registration: the student's mobile-number last
four digits, one shared password entered by the operator, or a separate random
password for each student. Mobile-number last four digits is the default.

## 2. Delivered Behavior

- The same three-option selector is available in administrator student,
  lecture, session-enrollment, and teacher student-import surfaces.
- Phone-last-four mode validates every student's personal mobile number before
  registration and identifies missing or invalid numbers without submitting.
- Shared-password mode requires a password of at least four characters and
  never persists the plaintext input in the job payload.
- Random mode creates a distinct four-digit password per newly created
  student. The completed credential list downloads automatically as an Excel
  workbook and remains manually downloadable from the import workbox during
  its bounded recovery window.
- Every account created by Excel import must change its password on first
  login, regardless of the selected initial-password mode.
- The existing import confirmation, background job, duplicate handling, and
  welcome-notification flows remain intact.

## 3. Security and Data Lifecycle

- Shared-password input and random credential output are encrypted with a key
  derived from the Django application secret before database persistence.
- Redis job progress receives only a sanitized result; plaintext credentials
  are not stored in Redis or browser storage.
- Authorized active staff can recover the encrypted random credential result
  for one hour after completion. The server rejects other tenants, non-staff
  users, and expired results.
- Browser recovery metadata contains job identity and completion timing only.
  Logout clears the workbox and its metadata.
- Job completion and student/account mutations share a database transaction;
  Redis completion publication happens only after commit.
- Input secrets are scrubbed on success, worker failure, and publish failure.

## 4. Compatibility and UX

- No database migration or infrastructure change was required.
- Existing clients that omit the password mode receive the new default,
  phone-number last four digits.
- The selector, validation messages, completion workbox, and mobile workbox
  offset were reviewed on administrator and teacher paths.
- The random-password workbook contains only the newly registered students'
  name, login ID, and initial password.
