# V1.12.6 Release Notes

**Status:** Production-deployed / GO with one controlled generic-verifier warning

**Release date:** 2026-07-29 KST

**Scope:** Teacher-controlled correction completion, regular/supplement score
separation, score/rank/top-percentile trends, responsive score reporting, and
the isolated preproduction database-boundary repair required for safe delivery

## 1. Decision

GO. Teachers can now separate regular lessons from supplement sessions in the
cumulative score view, inspect score, rank, or top-percentile trends, and
manually mark each exam or homework correction as complete without changing
the recorded score or automatic pass/fail result.

The completion state is intentionally version-bound to the source score.
Editing a score after correction review reopens the correction, so an outdated
teacher confirmation cannot remain silently complete. Pending correction
states remain visible in the roster and in the student drawer.

The release passed the isolated candidate migration and health gate before any
production mutation, then completed an expand-only production migration,
health-gated API/worker replacement, Cloudflare deployment, production
round-trip E2E, and an independent 30-check PostDeploy canary.

## 2. Product and Implementation

- Add a compact regular/supplement/all filter to cumulative session results.
- Add score, rank, and top-percentile trend modes without duplicating charts or
  adding a second reporting surface.
- State the ranking contract in the UI: first-attempt score, dense rank, and
  non-submissions excluded from the ranked cohort.
- Add teacher-controlled correction completion for each exam and homework
  source in the existing student detail drawer.
- Keep correction completion independent from score, automatic cutoff, and
  pass/fail state.
- Highlight students with a pending correction while keeping automatic
  assessment warnings intact.
- Invalidate a completion automatically when the source score's `updated_at`
  changes.
- Treat perfect-score sources as not requiring correction.
- Preserve responsive teacher, student, parent, mobile, dark-mode, long-history,
  loading, empty, and error states in the shared trend component.
- Ship the concurrently integrated branded responsive score-report work and
  source-matched Problem Studio worksheet controls on the same verified
  frontend head.

## 3. Data and Safety Contract

- Add only the new `progress_assessmentcorrection` table; no existing table,
  column, or user-authored score is removed or rewritten.
- Uniquely bind a correction to tenant, enrollment, session, source type, and
  source ID.
- Resolve every correction write through the authenticated staff tenant,
  session tenant, lecture attendance roster, and exact exam/homework source.
- Reject students outside the session attendance roster.
- Use transactions and row locks for correction updates.
- Preserve manual state independently from score edits while using the score
  version snapshot to reopen stale completions.
- Keep score trend reads tenant-scoped. Ranking uses the existing canonical
  first-attempt analytics contract.
- Preserve fail-closed behavior for missing tenant, session, roster, or source
  boundaries.

## 4. Product Review

- The completion control lives in the existing right drawer instead of adding
  another table column or top-level page.
- The trend selector reuses one chart and one summary layout, keeping the
  interface legible for teachers who only need scores.
- Ranking and percentile descriptions explicitly mention first-attempt scores
  after the product audit identified that policy as otherwise easy to
  misunderstand.
- Regular/supplement filtering is generic for other academies and does not
  encode a specific subject or weekend-clinic name.
- Empty, API-error, and insufficient-cohort states remain distinct; an error is
  never presented as a real zero.

## 6. Controlled Residuals

- Rank and top-percentile views are meaningful only when a ranked cohort
  exists; insufficient cohorts retain an explicit empty/insufficient state.
- Ranking intentionally uses first attempts. A future policy change to best or
  latest attempts must be a separate product decision.
- Correction completion is a teacher confirmation, not an automatic score
  override. Editing the score intentionally reopens it.
- The generic read-only deployment verifier reports `CONDITIONAL GO` because
  local `wrangler r2 bucket list` credentials are unavailable. This release
  does not change R2. Frontend 200 responses, hashed-asset cache headers, CORS,
  Cloudflare deployment, version propagation, production E2E, and the signed
  CDN playback chain were verified independently.
- Concurrent Problem Studio and responsive score-report commits are included
  in the deployed heads and passed the same backend/frontend production gates.
