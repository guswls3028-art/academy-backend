# V1.11.8 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-26 KST

**Scope:** Single-recipient incident SMS hardening, safe tenant/reason context,
at-most-once external-signal delivery, and bounded production authentication

## 1. Decision

GO. User-impacting backend and frontend incidents are evaluated every five
minutes and can notify only the controlled operator number. The SMS gives the
operator the affected tenant code/internal ID and a privacy-safe reason so the
operator can contact the academy before waiting for an inbound report.

No user phone number, name, request body, free-form exception text, or
credential is placed in an incident SMS or its audit receipt.

## 2. Delivered Behavior

- User-incident SMS delivery remains fixed to `01031217466`; both the Solapi
  sender and recipient must normalize to that exact controlled number.
- A mismatched sender or recipient fails before the provider client is called.
- Tenant-attributed messages contain the tenant code/internal ID and bounded
  reason counters such as server 500, frontend error, or request failure.
- The aggregate SMS remains forced to the SMS channel and is capped at 90
  UTF-8 bytes.
- Provider registration is followed by delivery-group polling. The audit
  receipt records only the recipient last four digits, provider group ID, and
  delivery counters.
- Ambiguous provider outcomes are reconciled before a later send; cooldown and
  rate-cap enforcement remain fail-closed.
- The independent CloudWatch API-impact fallback now writes
  `claimed:<transition>` before SSM dispatch and `delivered:<transition>` only
  after success. A lost response therefore suppresses automatic duplicate
  sends for the same alarm transition.
- Manual `dry_run=true` keeps the default `--rule user_incidents` scope instead
  of broadening to every alert rule. Dispatch inputs are passed through step
  environment variables and strictly validated as booleans.
- Every production AWS OIDC credential step has a 180-second action timeout.
  A stalled authentication call can no longer retain the shared production
  mutation lock for hours.

## 3. Compatibility and Data Safety

- No database model or migration changed.
- Tenant selection and tenant isolation contracts are unchanged.
- The scheduled five-minute user-incident evaluation and hourly full-rule
  evaluation remain backward compatible.
- SMS is the only incident-notification channel in this path.
- CloudWatch fallback transition state remains compatible with the former raw
  timestamp value as well as the new claimed/delivered values.
- No destructive production data operation or test tenant was created.
