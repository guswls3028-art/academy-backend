# V1.11.31 Release Notes

**Status:** Production-deployed / GO for developer-console operations

**Release date:** 2026-07-28 KST

**Scope:** Final production closure for the isolated developer-console origin,
real-use unified inbox, iPhone home-screen identity, and durable platform push
delivery

## 1. Decision

GO for platform owners to use `https://dev.hakwonplus.com` as the canonical
developer console.

The production console now opens directly at the unified inquiry inbox, shows
real support, lead, feedback, bug, and incident records, and no longer includes
the unused agent-monitor surface. The installable iPhone web app has its own
HakwonPlus console identity, while teacher and student web apps continue to use
each tenant's branding.

The previously red production student-login canary was also closed without
weakening or skipping the gate. Its dedicated non-user production fixture and
GitHub Actions credentials were reconciled, and the same frontend workflow now
passes end to end.

## 2. Production Behavior

- `https://dev.hakwonplus.com/` permanently redirects to `/dev/inbox`.
- Legacy `https://hakwonplus.com/dev/*` URLs permanently redirect to the new
  origin while preserving the path and query string.
- The developer origin is tenant-bound, non-indexable, and restricted to
  developer, login, and legal routes.
- The production unified inbox returned three live contact records during the
  release verification. The operator UI rendered the summary, list, and first
  inquiry detail successfully.
- The agent-monitor navigation and route are absent.
- The developer manifest installs as `학원플러스 콘솔`, starts at
  `/dev/inbox`, uses standalone display mode, and serves valid 192 px and
  512 px HakwonPlus icons.
- Non-owner tenant manifests use only their tenant-specific icon assets and do
  not fall back to HakwonPlus branding.

## 3. Push Delivery

- The developer console registers the isolated service worker and exposes an
  explicit `알림 켜기` control.
- iPhone users who open the installed home-screen app can grant notification
  permission and register a platform-scoped subscription.
- Only an authenticated active platform owner can create or remove a platform
  subscription or obtain the VAPID public key.
- New contacts, bug reports, feedback, and incidents are written to a durable,
  deduplicated outbox. The five-minute production cron dispatches due items,
  retries transient failures with a bounded backoff, and disables stale push
  endpoints.
- Push payloads contain only a generic category and count and open
  `/dev/inbox`; inquiry content and personal details are not copied into the
  notification.
- Both production VAPID keys and the owner-tenant binding are configured. No
  platform subscription is fabricated server-side: the initial active count is
  zero until the operator performs the required iPhone user gesture.

## 6. Audit Closure

The release was reviewed through all six version-seal lenses in the primary
execution thread.

- Backend domain: inbox aggregation, status/reply boundaries, durable outbox,
  retry state, and stale-subscription handling were verified against source and
  focused tests.
- Tenant isolation: platform subscription endpoints require the platform-owner
  permission; ordinary tenant owners and teachers cannot subscribe to the
  platform channel. Tenant manifests remain brand-isolated.
- Frontend integration: the console uses the platform push endpoint family,
  waits for the registered service worker, handles iOS standalone detection,
  and routes notification clicks to the real inbox.
- Destructive and boundary behavior: support retries are idempotent, follow-up
  messages reopen rather than replace records, status mutations preserve source
  records, and no live inquiry was changed during verification.
- UX and accessibility: loading, empty, failure, blocked-permission, and iPhone
  installation guidance are explicit; the notification control exposes its
  state and the unused agent navigation is removed.
- Security: authentication and platform-owner authorization fail closed,
  arbitrary/private push endpoints are rejected, CORS is exact-origin, the
  console is non-indexable, and notification payloads exclude private inquiry
  content.

Critical findings: 0. High findings: 0 after closure.
