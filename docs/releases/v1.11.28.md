# V1.11.28 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-28 KST

**Scope:** Deploy-safe API user-impact alarms and operator-readable incident SMS

## 1. Decision

GO for the API user-impact monitoring correction. The SMS received at
2026-07-27 23:36 KST was a deployment false positive, not an observed API
outage. The production alarm now triggers on a target 5xx burst or zero healthy
API targets, while expected warm-up targets during a zero-downtime deployment
do not produce an operator incident.

## 2. Incident Evidence and Root Cause

- `academy-api-UserImpact` entered `ALARM` at 23:34:57 KST because
  `academy-api-UnHealthyHosts` evaluated a five-minute
  `UnHealthyHostCount Maximum >= 1`.
- During that same deployment window, `HealthyHostCount` never dropped below
  1, target and ALB 5xx metrics had no datapoints, and both `/health` and
  `/healthz` returned HTTP 200.
- The deployment deliberately increased API capacity before its instance
  refresh. Newly registered targets briefly appeared unhealthy while an
  existing healthy target continued serving traffic.
- The prior alarm treated any warming target as user impact, so every normal
  deployment could create the same SMS.

## 3. Repair and Recurrence Prevention

- The existing `academy-api-UnHealthyHosts` resource now evaluates
  `HealthyHostCount Minimum < 1` instead of
  `UnHealthyHostCount Maximum >= 1`.
- The zero-healthy threshold is fixed to 1 in the alarm definition rather than
  exposed as a configurable value that could exceed the API desired capacity.
- Missing `HealthyHostCount` data is treated as breaching so a target group
  with no registered targets remains fail-closed.
- The independent target 5xx alarm remains unchanged at 10 errors per
  five-minute period for two evaluation periods.
- The operator SMS now says `5xx 급증 또는 정상 서버 0대` instead of the
  ambiguous `API 오류/비정상 대상`.
- Static infrastructure coverage prevents a return to
  `UnHealthyHostCount`, a configurable zero-healthy threshold, or ambiguous
  SMS copy.

## 4. Compatibility and Boundaries
