# V1.11.17 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-27 KST

**Scope:** Absence-safe Excel result imports, cumulative non-submission
visibility, corrected score/stat semantics, and full production closure

## 1. Decision

GO. A teacher can now mark an exam row as `결시` in the generated result
workbook. That explicit marker takes precedence over blank question cells, so
an absent student is no longer interpreted as receiving every question
correct. The absence is stored in the existing canonical attempt status,
excluded from score-based calculations, and remains visible through cumulative
gray student-name shading in later workbooks and administrator score screens.

## 2. Root Cause and Delivered Behavior

- The importer intentionally treats a blank question cell as correct to support
  teacher workflows that record only wrong answers. The generated workbook did
  not provide a separate absence field, so a fully blank row was
  indistinguishable from a perfect score.
- The generated workbook now includes a `결시` column with a data-validation
  selection, guide text, an absence-aware score formula, and current-row name
  shading.
- The importer recognizes the explicit absence field before interpreting
  question marks. Preview shows the absence count and row state before apply.
- Applying an absence writes the representative attempt's existing
  `NOT_SUBMITTED` status, clears stale per-question snapshots, and records a
  non-scoring audit fact without adding a database schema or migration.
- Re-downloading the same exam pre-fills `결시` for students already marked
  absent. A workbook round trip therefore cannot silently turn a known absence
  back into a perfect score.
- A later normal result import clears the absence for that exam and rebuilds
  the student's result items. This gives teachers a safe correction path for
  an accidental absence mark.
- Current and prior regular-exam absences are counted by tenant, student, and
  distinct exam. The workbook adds static gray name shading and a
  `누적 미응시 N회` comment; administrator score tables and drawers show the
  same cumulative gray cue and accessible title.
- Clinic-target highlighting remains a separate yellow state. When both states
  apply, the existing clinic meaning remains distinguishable from the new
  absence history.
- Absent attempts remain part of the detailed exam headcount contract, but
  their score is exposed as missing and they are excluded from score, average,
  rank, pass/fail, and question-correctness calculations.
- Question statistics now select the latest fact per attempt, enrollment, and
  question so a corrected import does not double-count older facts.
- Existing workbooks remain compatible. The corrective behavior activates only
  when a supported absence header and marker are present; otherwise the
  established blank-cell grading rule is unchanged.

## 3. Compatibility and Data Safety

- No database migration, infrastructure change, authentication change, or
  tenant-resolution change was introduced.
- The canonical `ExamAttempt.meta.status = NOT_SUBMITTED` state is reused; no
  parallel absence store was created.
- Cumulative counts are tenant-scoped and count distinct regular exams only.
- Preview is non-mutating. Apply remains inside the existing result-import
  transaction and uses the existing enrollment and exam ownership boundaries.
- An absence retains an internal non-null zero only where the existing database
  constraint requires it. Public/admin result contracts expose the score as
  missing so zero-score and perfect-score semantics are not conflated.
- The correction path preserves the first real scored attempt as the initial
  snapshot instead of treating an absence placeholder as a scored baseline.

## 4. Six-Lens Release Review

- **Domain correctness:** the explicit absence marker overrides question-cell
  interpretation, and ordinary imports deliberately clear a prior absence.
- **Tenant isolation:** absence history is derived only from the current
  tenant's representative regular-exam attempts and distinct exam identities.
- **Data lifecycle:** preview, apply, re-download, normal correction, result
  item cleanup, initial snapshot, and audit-fact behavior were tested together.
- **Analytics:** absence is missing rather than zero in score projections and
  is excluded from rank, average, pass/fail, and question statistics while the
  established detailed headcount contract is preserved.
- **UX and accessibility:** desktop and 390-pixel views were exercised with the
  real import component; the gray state, `누적 미응시 N회` title, preview
  summary, and `결시 반영` row outcome remain visible without horizontal
  overflow.
- **Operations and regression:** backend checks, focused and smoke tests,
  frontend static checks/build, deployment workflows, post-deploy verification,
  production canary, image-digest verification, and frontend revision
  verification all passed.

This review was performed as a complete main-agent release audit. No claim of
independent reviewer separation is made.
