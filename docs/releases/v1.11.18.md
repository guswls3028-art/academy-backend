## 감사 결과

- Backend domain: 결제 상태 전이, idempotency, 60초 Toss 타임아웃 유지
- Tenant isolation: 카드 등록·삭제·조회는 원장 권한과 요청 tenant에 묶임
- Frontend integration: SDK v2 파라미터와 서버 콜백 계약 일치
- Destructive/race: 카드 mutation과 결제 claim을 Program row lock으로 직렬화
- UX/accessibility: Toss 취소·실패 콜백을 사용자 메시지로 수렴
- Security: 테스트/라이브 키 혼용 차단, 비밀값 로그·프로세스 인자 노출 차단,
  빌링키 암호화·fingerprint 조회 적용
- 알려진 critical/high 결함 없음

## 의도적으로 보류된 외부 단계

- 운영 SSM의 Toss client/secret key는 아직 비어 있고
  `TOSS_AUTO_BILLING_ENABLED=false`를 유지한다.
- Toss 자동결제 추가 계약이 완료된 MID의 같은 세트
  `live_ck_...` / `live_sk_...`가 필요하다.
- 운영 카드 등록 후 실제 승인 금액·대상 테넌트를 사용자와 다시 확인하기 전에는
  실결제를 실행하지 않는다.
- 전자세금계산서는 카드 자동결제와 별도 연동이다. 발행사, 청구/영수 시점,
  카드 매출전표와의 중복 증빙 정책, 발행사 운영 자격증명이 확정되기 전에는
  국세청 전송 상태로 올리지 않는다.
