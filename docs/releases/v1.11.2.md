# V1.11.2 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-26 KST

**Scope:** One unrestricted Academy plan with an exact monthly supply price of
KRW 145,000, VAT of KRW 14,000, and total charge of KRW 159,000

## 1. Decision

GO. Academy now presents and enforces one `all` plan for every tenant. The plan
contains the complete product feature set; fee management, AI OMR, and storage
are no longer gated by Standard, Pro, or Max tiers.

The VAT amount is an explicit product price, not a calculated percentage:
KRW 145,000 supply + KRW 14,000 VAT = KRW 159,000 total.

## 2. Delivered Behavior

- Public and in-app pricing surfaces show exactly one plan and the three exact
  amounts. Legacy Standard, Pro, and Max choices are absent.
- New and existing programs converge on plan code `all` with a monthly price of
  KRW 145,000.
- All authenticated tenant administrators retain the complete feature set.
  Fee management and AI OMR no longer reject a tenant based on its plan.
- Every tenant receives the same 200 GB storage quota; the former plan-based
  storage lock is removed.
- The plan-change API was removed because no alternate target plan exists.
- Billing, tenant-management, development-dashboard, audit, and production
  canary paths use the same canonical single-plan values.

## 3. Migration and Compatibility

- The backend shipped in two rolling-compatible phases, with the frontend
  deployed between them.
- Migration `0045_unify_subscription_plan` introduced the `all` plan while
  retaining legacy database choices during the rolling window.
- Migration `0046_apply_single_subscription_plan` finalized the model and data.
  It intentionally has no reverse data migration because reverting would
  require inventing a legacy tier for each tenant.
- All programs were normalized to `all` / KRW 145,000.
- Only `SCHEDULED` invoices were updated to KRW 145,000 supply, KRW 14,000 VAT,
  and KRW 159,000 total. Pending, failed, overdue, paid, and other historical
  invoice snapshots were preserved.

## 6. Residual Risk

- The existing aggregate storage-quota check is tenant-scoped but is not
  serialized across simultaneous uploads, so sufficiently concurrent uploads
  can theoretically overshoot the 200 GB limit. Individual uploads remain
  capped at 2 GB. A serialized quota ledger is deferred as a separate
  hardening change; this release neither introduced nor widened that behavior.

No release-scoped Critical or High finding remains.
