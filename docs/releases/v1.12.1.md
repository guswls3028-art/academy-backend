## 2. Hidden bugs and repairs

- The QnA verification wrapper still called a removed management command. It
  now invokes the bounded safe verifier.
- The verifier could choose a student outside the requested tenant and relied
  on a stale hard-coded student ID. Student selection is now tenant-bound,
  active-only, non-deleted, and automatic only when the result is unambiguous.
- The wrapper posted to the internal HTTP ALB. Its 301 redirect could rewrite
  POST to GET and produce a false-positive empty-list response. Verification
  now stays on the canonical HTTPS origin.
- Wrong-note PDF polling could be lost after navigation or reload. The
  frontend now persists the active request identity, resumes bounded polling,
  refreshes expired signed URLs, and rejects stale request fingerprints.
- Concurrent score edits could race through overlapping PATCH requests.
  Writes are serialized and their query invalidation is ordered.
- Frontend build-time environment and public metadata handling were aligned
  with Vite's executable configuration boundary.

## 3. Reliability and optimization

- API replacement remained rolling and health-gated; repeated live health
  probes returned HTTP 200.
- Tools and AI workers retain the intended scale-to-zero baseline when idle.
- The Tools worker launch template is pinned to the immutable digest promoted
  by the verified release manifest.
- Wrong-note recovery reuses the existing job instead of starting duplicate
  generation after a reload.
- Score saves are coalesced through one serial queue, removing avoidable
  overlapping requests and stale cache races.
- The QnA production verifier creates one tagged record, proves list
  visibility, deletes it, and leaves no tagged residue.
