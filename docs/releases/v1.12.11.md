# V1.12.11 Release Notes

**Status:** Production-deployed / GO

**Release date:** 2026-07-30 KST

**Scope:** Preserved dirty-worktree integration, canonical workspace navigation,
Problem Studio compatibility, score/report/YMath regression closure, and
production stabilization

## 1. Decision

GO. The useful parts of the preserved backend and frontend dirty worktrees were
integrated on top of the latest deployed `main` branches without replacing
newer score-correction, YMath splitting, score-report pagination, equation
preservation, preproduction isolation, or immutable image-promotion safeguards.

The frontend now uses canonical workspace navigation throughout the maintained
browser regression estate, provides an accessible teacher navigation accordion,
and sends internal product-update routes to the public updates page. Problem
Studio normalizes partial saved document-style payloads against durable defaults
so older records or version-skewed API responses cannot make controlled fields
undefined.

The backend product behavior is unchanged by this patch. Its release-scoped
changes consolidate operational guidance, remove the obsolete root
`deploy.ps1` alias, and point current documentation to
`scripts/v1/deploy.ps1`. Messaging remains at one warm production worker, while
AI and Tools retain their queue-driven scale-to-zero contracts.

## 2. Product and Implementation

- Preserve current score-entry and correction behavior, including empty versus
  zero scores, draft recovery, retry, undo/redo, mobile entry, explicit locking,
  and concurrent-editor fencing.
- Preserve the current YMath original-paper upload and automatic question split
  implementation instead of importing older splitter and renderer drafts.
- Preserve the responsive teacher and student/parent score-report generator,
  including the dense Korean 16-question three-page overflow guard.
- Normalize Problem Studio document styles after both load and save by merging
  partial API payloads with `DEFAULT_DOCUMENT_STYLE`.
- Convert teacher navigation groups to accessible accordions that automatically
  expose the current group, preserve task state, and respect reduced motion.
- Route owner and teacher product-update entries to the public
  `https://hakwonplus.com/promo/updates` page through an accessible external
  redirect.
- Move maintained admin/teacher browser contracts to `/workspace` and
  `/workspace/mobile`.
- Replace production-dependent score-entry discovery in the focused regression
  with deterministic, tenant-bound local API stubs while retaining the complete
  autosave/correction contract.
- Remove the obsolete generated E2E findings artifact and legacy root deployment
  alias.

## 3. Data and Safety Contract

- Tenant resolution remains fail-closed. No default tenant, tenant inference, or
  cross-tenant fallback was introduced.
- No user-authored, approved, score, message, file, R2, queue payload, or
  credential data was deleted or rewritten.
- The original dirty worktrees were never reset, rebased, staged, or used
  directly as production release inputs. Integration happened in clean
  `origin/main`-based worktrees.
- Older dirty drafts that would have removed report overflow checks, source
  equation markers, safe result-map lookup, retry-safe image promotion, or
  release-bound preproduction protections were intentionally not imported.
- The production Tools ASG remains `min=0`, `desired=0`, `max=2`; the persistent
  development host runs the separate Tools process for Excel/PPT/R2 real-use
  smoke.
- Messaging remains `min=1`, `desired=1`, `max=3` because account recovery and
  approved Alimtalk are user-waiting flows.
- The release introduced no new migration. Django migration dry-run reported no
  changes, and the official production migration job completed successfully.

## 4. Audit Findings and Fixes

- Found and fixed a real Problem Studio compatibility defect: partial saved
  style responses could transition controlled fields to `undefined`.
- Found and removed a stale dirty-worktree claim that production Tools should
  keep one warm instance; executable SSOT and deployment contracts require
  scale-to-zero.
- Found and fixed ambiguous current-document references to the deleted root
  `deploy.ps1`; all owning operations documents now name the canonical script.
- Found one PR-only CI failure where a tracked `_local` E2E file is intentionally
  ignored by ESLint but was included in the changed-file strict lint list. The
  unnecessary local-only route edit was removed; the same strict lint then
  passed for 153 changed TypeScript files.
- The selected frontend integration kept newer report and deployment contracts
  while retaining the unique navigation, accessibility, route, and Problem
  Studio improvements.
