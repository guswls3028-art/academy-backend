### 2026-08-09 assessment policy stabilization

The post-release Ymath exam-policy incident exposed a PostgreSQL-only failure:
the tenant-scoped exam queryset used `DISTINCT` and the policy PATCH then applied
`SELECT FOR UPDATE` to that result. PostgreSQL rejects that combination, so an
otherwise valid save for exam 763 (15-point written/correctness grading with a
0-point pass threshold) returned 500 before serializer validation.

The stabilization makes `Exam.tenant` the sole fail-closed ownership boundary,
removes the joined-session `DISTINCT` fallback from the locked update query, and
keeps the optimistic-concurrency row lock. It also seals the adjacent policy
bounds: a 0-point pass threshold remains valid, while non-positive maximum
scores, negative pass thresholds, and enabled retakes below two attempts are
rejected by both API and model validation. Frontend policy saves
preserve the edited form and show DRF field errors instead of a generic HTTP
failure. The owning regression covers the production-shaped 15/0 policy,
concurrency, publication, dates, retakes, grading modes, and server-error UX.

The first stabilization candidate then failed closed before development because
ECR detected `CVE-2026-58016` in the redundant system GLib package installed by
the AI image. Debian stable had no fixed package, while both governed OpenCV
runtimes already use the upstream headless wheel with no GUI/GLib dependency.
The AI and Video images therefore remove that unused package instead of adding
a Critical-risk exception; image import/video smoke and the completed ECR scan
remain mandatory before any production mutation.
