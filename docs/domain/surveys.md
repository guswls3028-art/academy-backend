# 설문·성적 취합

## 목적과 소유

교직원이 보강 신청, 시험 범위·상담 정보, 학교·모의고사 성적을 수집하고 학생별 응답·미응답과 선택형 통계를 확인한다. `apps/domains/surveys`가 설문·대상·응답을 소유한다. 외부 학생/인벤토리/성적 접근은 `apps/support/surveys.py`를 거친다.

화면과 복구 동작은 [frontend SURVEYS.md](https://github.com/guswls3028-art/academy-frontend/blob/main/docs/SURVEYS.md)가 소유한다. 성적 검수·통계의 기존 소유자는 [results README](../../apps/domains/results/README.md), 원본 저장·삭제는 [inventory-storage](inventory-storage.md), 학생 삭제는 [student-lifecycle](student-lifecycle.md)다.

## 권한과 상태

- 모든 직원 API는 요청 학원의 유효 교직원만 사용할 수 있다. 학생 API는 기존 학생 인증 또는 연결된 학부모의 명시적 `X-Student-Id` 선택을 사용한다. 자녀 누락·다른 학원/자녀·비대상 설문은 거부한다.
- 일반(`general`), 성적 취합(`school_score`), 학생 메모(`memo`) 유형을 제공한다. 작성 중→응답 시작→마감→재개를 지원한다.
- 최초 응답 시작 시 현재 대상 학생을 `SurveyRecipient`에 고정한다. API는 전체/개별/강의 대상을 지원하며 UI는 전체/개별 선택을 제공한다. 최대 10,000명이고, 나중에 등록한 학생을 소급 추가하지 않는다.
- 배포 후 질문·유형·시험 설정·대상·첨부 설정은 불변이다. 제목·안내·응답 기간·정원은 버전 확인 후 수정한다. 정원은 이미 제출한 인원보다 줄일 수 없다.
- 설문 응답은 별도 기록이다. 메모 설문이 교사가 쓴 공통 메모를 덮어쓰거나 성적을 자동 승인하지 않는다.

## API와 저장

`/api/v1/surveys/` 아래에 목록/생성, `student-choices/`, `{id}/` 조회/수정, `{id}/publish/`, `{id}/close/`, `{id}/responses/`, `{id}/statistics/`, `{id}/export/`, `students/{student_id}/responses/`를 둔다. 학생은 `student/`, `student/{id}/`, `student/{id}/response/`(PUT)를 사용한다.

목록은 `offset`(0..100000)·`limit`(1..100, 기본30)을 검증한다. 교직원 목록은 제목·상태, 응답 목록과 CSV는 `response_status=all|answered|unanswered` 및 학생 이름 검색을 지원한다. 직원의 학생 검색은 이름 기준 최대100명이다.

생성 요청은 학원별 UUID `creation_key`로 중복 저장을 방지한다. 수정/배포/마감은 `expected_version`, 응답은 `answers`, `attachment_ids`, `score_submission_ids`, `expected_version`을 받는다. 최초 응답 버전은0, 저장 후1이다. 동일 응답 재전송은 마감 후에도 기존 성공 결과를 돌려주며 변경·오래된 버전은409다.

질문은30개, 선택지는2..30개, 짧은 글500자/긴 글5000자, 전체 답변 JSON40KB로 제한한다. 응답 학생 저장소 잠금과 설문 행 잠금을 트랜잭션 안에서 획득해 삭제·중복·정원 경쟁을 직렬화한다. 정원이 차도 기존 응답자는 기간 내 수정할 수 있다.

## 원본과 성적

첨부는 본인의 JPG/PNG/PDF, 파일당20MB, 최대10개다. 성적 취합에는 본인의 `pending` 또는 `verified` 제출 기록이 필요하고, 설정한 시험 종류·학년도·학기·시기·월·과목과 일치해야 한다. 원본 파일을 함께 연결하며 기존 성적 제출 API와 교직원 검수를 재사용한다. 반려/통계 제외 결과도 응답 조회 시 현재 상태로 표시한다.

제출된 첨부는 인벤토리 삭제·이동·덮어쓰기로 사라지지 않도록409로 보호한다. 기간 내 응답 수정으로 연결을 해제할 수 있다. 마감된 설문은 직원이 재개해야 응답을 바꿀 수 있다. 성적 검수 원본의 별도 보존 규칙은 해제되지 않는다.

학생 영구삭제는 기존 정확한 대상·학원 확인 절차 안에서 해당 학생의 응답/M2M/대상을 먼저 삭제한다. 설문과 다른 학생의 응답은 보존한다. 학생 휴지통 이동/복원은 기존 정책을 따른다.

API와 worker 설정 모두 설문 ORM을 등록한다. 공유 학생 정리·인벤토리 보호 경로에서 설문 관계를 확인할 수 있어야 하며, 별도 설문 워커나 큐를 추가하지 않는다. `test_worker_settings_drift.py`의 설정 일치·worker 부팅/FK 검증으로 이 경계를 확인한다.

## 통계·내보내기·복구

선택형 통계는 저장된 응답에서 계산한다. CSV는 UTF-8 BOM, 수식 주입 방지, 100명씩 메모리 제한 처리, 사용자별 분당4회 제한으로 제공한다. 내보내기 제한은 일반 화면 조회와 별도 횟수를 사용한다. 원본 다운로드는 기존 인증된 인벤토리 presign 권한 검사를 통과해야 한다.

입력 오류400·권한403·비대상404·마감/정원/버전충돌409는 상세 이유를 돌려준다. 실패한 응답을 성공으로 표시하거나 선생님 확인 상태를 임의 변경하지 않는다. 로그인 없는 링크·자동 알림톡은 이 계약에 포함하지 않는다. 설문용 승인 템플릿 없이 다른 알림 봉투나 SMS/LMS로 대체하지 않으며 [messaging-policy](../ssot/messaging-policy.md)를 유지한다.

검증은 `surveys/tests/test_surveys.py`의 작성→배포→학생/학부모 응답→재조회/통계/CSV·마감/재개·자료 보호·영구삭제 시나리오, PostgreSQL `test_capacity_pg.py`의 마지막 한 자리 동시 신청을 포함한다. 운영 반영은 기존 격리 개발·preprod·동일 후보 배포 게이트를 통과해야 한다.

배포는 추가 테이블 migration→전체 API 교체·확인→프런트 순서다. 새 설문 쓰기 UI를 구 API와 섞어 먼저 배포하지 않는다. 프런트 rollback 시 서버와 추가 테이블·응답은 보존한다. 응답이 생성된 뒤 설문 관계를 모르는 구 서버로 rollback하면 기존 학생 영구삭제가 새 FK 때문에 실패할 수 있으므로, 해당 정리 지원을 포함한 호환 후보를 사용하거나 서버를 수정 배포한다. 데이터 삭제를 rollback 수단으로 삼지 않는다.
