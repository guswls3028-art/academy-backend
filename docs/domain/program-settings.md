# 프로그램 표시·기능 설정

`GET/PATCH /api/v1/core/program/`는 요청 학원의 표시 이름·브랜드·로그인 화면과
기능 설정을 제공한다. 공개 GET은 학원 문맥이 필요하며 읽기 중 Program을 만들지
않는다. 누락된 Program은 404로 표시하고 다른 학원 설정으로 대체하지 않는다.

PATCH는 현재 학원의 활성 교직원에게 허용한다. 요금제·활성 여부·기능 플래그는
기존 owner/superuser 검증을 추가로 통과해야 한다. 구독 만료·해지·가격·청구 필드는
이 API의 수정 대상이 아니며 billing 서비스가 소유한다.

부분 저장은 Program 행을 잠그고 최신 값에 요청 필드만 적용한다. 다른 담당자의
브랜드 변경이나 billing의 해지 예약을 오래된 조회값으로 덮어쓰지 않는다. 응답도
실제 저장한 최신 행에서 만들며 다시 GET한 결과와 일치한다. `feature_flags`와
`ui_config`는 JSON 객체만 허용한다. 배열·문자열 설정 및 객체가 아닌 요청 본문은
400으로 거부하고 기존 설정을 보존한다. 올바른 객체로 정정 후 재시도할 수 있다.

Program JSON 객체 자체는 해당 필드의 교체 계약을 유지한다. 별도 원장 학원 정보
API `/core/tenant-info/`의 목록 저장은 `expected_academies`를 최신 잠긴 Tenant의
목록과 비교한다. 불일치하면 전체 요청을 `409 settings_conflict`로 거부하고 최신
목록을 돌려준다. 화면은 편집 시작 시의 목록을 고정하여 백그라운드 재조회로
기준을 바꾸지 않는다. 초안은 유지하며 사용자가 최신 목록에서 다시 수정하기를
선택하면 명시적으로 초안을 버리고 재조회한다. 최신 목록에 수정·추가·삭제 후
reload와 학생 홈에 같은 결과가 표시되어야 한다.

개발자 브랜딩 `/core/tenant-branding/:id/`도 표시명·창 제목·로그인 제목·부제의
원본을 `expected`로 보내 잠긴 Program의 최신 값과 비교한다. 충돌은 같은 409이며
새 화면에서 최신값 확인 후 재작성할 수 있다. 표시명과 ui_config는 한 거래에서
저장한다. 로고 업로드는 R2 I/O 후 행을 새로 잠그고 로고 키만 병합하므로 그동안
저장된 다른 브랜딩 필드를 되돌리지 않는다. 원본 비교 필드는 구버전 화면과의
순차 배포 호환을 위해 선택 사항이며, 새 화면은 항상 전송한다. 구버전 화면이나
일반 Program JSON 교체 API 전체에 새 충돌 방지가 적용됐다는 뜻은 아니다.
과거 저장 데이터를 자동 변경하거나 구독 정책·운영 HOLD를 해제하지 않는다.
브랜딩 PATCH는 JSON 객체와 문자열 필드만 허용한다. 표시명은 null을 받지 않고
모델의 120자 상한을 먼저 검사한다. 나머지 선택 제목·로고의 null 지우기는 유지한다.
잘못된 배열·숫자·참거짓 입력은 400으로 거부하여 기존 공개 제목과 로고를 보존하고,
문자열로 고친 뒤 정상 저장·재조회할 수 있다.
화면 상호작용은 frontend `docs/USER-GUIDE-ADMIN.md`와 설정 화면이 소유한다.

검증: `apps/core/tests/test_program_update_integrity.py`에서 오래된 표시 설정 수정
뒤 해지 예약·다른 설정 보존, 응답·reload 일치, 잘못된 JSON의 무변경 및 정상 재시도를
확인한다. 관련 구독 전이와 테넌트·역할 경계는 billing/core 회귀로 함께 확인한다.
