# 학교 성적 취합

학생은 학년도와 회차를 선택해 중간·기말고사 과목 성적을 직접 입력한다. 교직원은
선생앱에서 같은 범위의 명단, 제출·미제출 집계, 학생별 과목 성적을 확인한다.
학원 내부 시험 성적과 기존 파일 첨부 제출, 성적 취합 설문은 독립적으로 유지한다.

- 범위는 2000–2100학년도, 1/2학기, 1차(중간) 또는 2차(기말)다. 학생 본인의
  활성 학원 계정만 조회·저장할 수 있다. 별도 학생 ID나 자녀 헤더로 대상을 바꿀
  수 없다.
- 학생 조회·저장: `GET|PUT /results/school-reports/me/?academic_year=2026&semester=1&exam_round=first`.
  저장은 `{subjects: [...]}` (1–20개 과목)으로 원자적으로 처리한다. 필수 값은
  `subject`, `score`, `max_score`이며 점수는 소수점 둘째 자리까지 입력한다.
  응답의 `direct_scores`는 본인이 다시 편집할 목록, `scores`는 해당 회차의
  과목별 최신 활성 제출이다. 같은 내용의 재저장은 행을 중복 생성하지 않는다.
  기존 직접 입력 과목에서 생략한 선택 지표는 유지되며 명시적 `null`로 지운다.
- 교직원 조회: `GET /results/school-reports/` 및
  `GET /results/school-reports/{student_id}/`에 같은 회차 쿼리를 사용한다. 명단은
  삭제되지 않은 현재 학원 학생을 사용하고, 선택 강의에는 활성 수강만 포함한다.
  `search`(이름·학교)와 `status`(submitted/missing)는 목록을 좁힌다. 상단
  제출·미제출 집계는 검색과 상태 조건에는 영향받지 않고 선택한 강의 범위는 따른다.
  다른 학원, 삭제된 학생, 비정상 증빙 연결은 조회하지 않는다.
- 제출 상태는 해당 회차에 직접 입력값이나 유효한 검토 대기/확인 완료 파일 첨부
  성적이 한 과목 이상 있는지에 따른다. 직접 입력은 `StudentReportedScore`의
  `direct_entry`와 활성 저장 상태 `self_entered`로 구분한다. 취합 API는 이를
  `pending`과 `direct_entry: true`로 표시한다. 학생은 동일 회차의 직접 입력값만 바꿀 수 있고,
  빠진 기존 직접 입력 행은 `self_removed` 상태로 남긴다. 파일 첨부 및 검수 이력을 수정하지
  않는다. 직접 입력값은 원본 확인 또는 승인 통계 대상이 아니며, 기존 파일 첨부
  제출·삭제·설문 증빙 규칙은 [인벤토리](inventory-storage.md)를 따른다.
- 교직원이 명시적으로 `POST /results/school-reports/requests/`에 회차와
  `student_ids`(최대 100명)를 보내면 대상 학생 앱 알림함에 요청을 등록한다.
  다른 학원·삭제된 학생이 포함되면 전체 실패하며, 제출 완료·비활성 계정·기존
  요청은 건너뛴다. 재시도해도 같은 학생과 회차에 알림이 중복 생성되지 않는다.
  요청 결과는 `requested`와 `skipped` 건수다. 알림은
  `GET /community/notifications/?kind=school_report_request`에서 본인만 읽으며,
  알림의 학년도·학기·회차로 학생 입력 화면을 연다.
- 학교 성적 제출 요청과 일치하는 카카오 승인 양식이 없어 알림톡은 제공하지 않는다.
  기존 성적 안내 양식은 실제 점수 통보 전용이다. 수동 앱 알림과 성적 저장은 메시징
  큐나 공급자에 연결되지 않으며 자동 발송도 없다. 승인 양식 활성화 경계는
  [메시징 정책](../ssot/messaging-policy.md)을 따른다.

검증은 `apps/domains/results/tests/test_school_report_collection.py`에서 학생
저장→재조회→교사 조회, 회차 분리, 기존 증빙 보존, 교직원 명단 격리, 수동 요청
중복 방지와 앱 알림 수신 범위를 확인한다.

두 스키마 변경은 기존 행을 변환하거나 지우지 않는다. 이전 런타임은 새 기본값으로
기존 원본 성적을 계속 저장할 수 있다. 사용자가 직접 입력하거나 앱 요청을 등록한
뒤에는 이전 앱 이미지를 사용하더라도 확장된 스키마를 유지한다. 이전 제약 또는
짧은 알림 유형 길이로 역마이그레이션해 사용자 데이터를 잃어서는 안 된다.
