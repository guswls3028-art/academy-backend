# 교직원 게시판

학원별 교직원은 공지사항, 자료실, 자유게시글을 읽고 작성하고 댓글로 협업한다. 기존·신규 학원 모두 별도 초기화 없이 같은 세 게시판을 사용한다. 현재 학원의 활성 owner, admin, staff, teacher 멤버십이 필요하다. 전역 관리자 표시만 가진 사용자, 학생, 학부모는 접근할 수 없다. 학생·학부모 커뮤니티 및 플랫폼 운영자 게시판과 데이터 모델을 공유하지 않는다.

기본 API 경로는 `/api/v1/staffs/board/posts/`다.

| 요청 | 동작 |
| --- | --- |
| GET | 최신 글부터 목록을 반환한다. category는 notice, resource, free 중 하나이며 page와 page_size를 지원한다. 기본·최대 20개이며 목록에서 본문은 제외한다. |
| POST | category, title(200자), body(20,000자)로 작성한다. 자료실은 multipart file 한 개(10 MiB 이하)를 첨부할 수 있다. |
| GET {id}/ | 글 본문, 작성자, 작성 시간, 첨부 표시명, 수정 가능 여부와 시간순 댓글을 조회한다. |
| PATCH {id}/ | 작성자만 제목·본문을 수정한다. 첨부 회수는 별도 DELETE 요청을 사용한다. 게시판 종류는 유지한다. |
| POST {id}/replies/ | body(5,000자)로 댓글을 작성한다. |
| GET {id}/attachment/ | 같은 학원 교직원의 권한을 확인한 뒤 원본을 바이너리로 내려준다. Content-Disposition은 표시 파일명, Cache-Control은 private, no-store다. 원본 부재는 404, 저장소 장애는 503이다. |
| DELETE {id}/attachment/ | 작성자 또는 현재 학원의 owner/admin이 첨부만 회수한다. 글·댓글은 남고 즉시 다시 내려받을 수 없게 된다. 반복 요청도 204다. 새 파일을 공유하려면 새 자료 글을 작성한다. |

글·댓글 POST는 UUID 형식의 선택적 `Idempotency-Key` 헤더를 받는다. 클라이언트는 같은 작성 시도의 재전송에 같은 키를 사용한다. 최초 저장은 201, 같은 학원·사용자·작성 대상에서 내용과 첨부 파일명이 같고 바이트도 동일한 재전송은 기존 글·댓글을 200으로 반환한다. 같은 키로 내용을 바꾸면 409, UUID 형식 오류는 400이다. 헤더 없는 기존 클라이언트는 요청마다 새 글을 작성한다. 작성자 수정이나 첨부 회수 뒤에 지난 제출을 재전송해도 해당 변경을 보존한다.

첨부는 비공개 Storage 버킷의 학원별 UUID 키에 저장한다. 업로드 전에 서버가 기존 Storage 정리 큐에 키를 커밋한다. 단일 PUT과 게시글 저장을 수행하는 동안 큐 행을 잠그고, 글 및 재전송 결과를 커밋할 때 정리 예약을 해제한다. 업로드 결과가 불확실하거나 API 프로세스가 중단되면 5분 안정화 기간 뒤 기존 정리 워커가 소유자 참조를 확인하고 원본을 회수한다. 첨부 회수는 키를 비우는 트랜잭션에서 정리 작업을 등록하고, 커밋 후 삭제를 재시도한다. 다른 학원의 글·댓글·첨부 조회는 404다.

역할 및 학원 격리, 글·댓글의 재전송, 첨부 원본의 다운로드·회수 및 업로드 중단 복구를 `apps.domains.staffs.tests.test_board`에서 검증한다.
