# 차시별 영상 권한

일반 강의 영상은 해당 tenant의 활성 학생·ACTIVE 강의 수강등록과 **정확한
SessionEnrollment**가 모두 있어야 시청할 수 있다. N차시 등록은 앞뒤 차시에
권한을 주지 않는다. 출결·진도·영상별 재생 설정은 차시 등록을 대신하지 않는다.

학생 및 학부모의 선택 자녀는 영상 홈에서 등록된 차시만 보고, 영상 수·시간·진도
집계도 그 차시를 기준으로 받는다. 직접 URL을 입력하더라도 차시 목록, 재생 시작,
access_check, 진도·댓글·좋아요 등 공통 context 소비자는 같은 권한을 확인한다.
SessionEnrollment의 tenant, 수강·학생·강의 tenant와 강의 일치가 모두 필요하다.

차시 등록을 해제하면 해당 차시의 새 재생과 기존 토큰 refresh/renew/heartbeat는
403으로 거절된다. 다른 등록 차시는 계속 정상 이용할 수 있다. 강의 수강등록을
INACTIVE로 바꾸면 일반 수강 권한은 전체 회수된다. 출결·성적·진도 이력은 이
권한 검사 변경으로 삭제하거나 다시 작성하지 않는다.

명시적 PUBLIC 영상과 시스템 공개 영상 공간은 기존 공개 계약을 유지한다.
교직원이 별도 승인한 inactive/direct 영상 권한도 기존 정확한 영상 단위 계약을
유지한다([direct-video-access.md](direct-video-access.md)). 일반 ACTIVE 수강의
차시 누락을 그 예외로 자동 보완하지 않는다.

판정 소유자는 `academy/application/use_cases/student_video_access_context.py`,
차시 관계 조회는 `repositories_video.video_session_memberships` 및
`session_enrollment_exists`, 토큰/발급 시 재검사는 `get_effective_access_mode`다.
학생 영상 홈·통계는 동일 관계 조회로 범위를 제한한다.

DB migration이나 API 응답 형식 변경은 없다. 구 frontend도 서버에서 같은 차시
검사를 받으며 페이지 강제 새로고침이나 일괄 세션 초기화를 요구하지 않는다.
이미 발급된 CDN URL 자체는 그 서명 만료까지 유효할 수 있으며, API의 즉시
권한 회수와 CDN 캐시/이미 내려받은 데이터의 삭제를 동일한 보장으로 취급하지 않는다.

감독형 재생을 새로 발급할 때 API 응답·토큰과 저장된 재생 세션은 하나의 절대 만료
시각을 사용한다. 발급 중 초 경계가 지나도 세션만 1초 늦게 남지 않는다. 만료된
재생은 현재 수강·차시 권한을 다시 확인한 뒤 새로 발급한다. 기존 세션 데이터의
마이그레이션이나 응답 형식 변경은 없다.

검증: `apps/domains/video/tests/test_session_video_entitlement.py`는 8차시 중
3차시만 등록, 홈/통계 범위, 정상 재생 후 차시 해제와 기존 토큰 재검사, 다른
차시 유지, 강의 INACTIVE, 공개 영상, 다른 tenant 관계를 실제 DB/API로 검증한다.
`tests/test_video_access_security.py`, `tests/test_direct_video_entitlement.py`와
inactive entitlement 회귀를 함께 실행한다. 운영 모양의 로그인·브라우저/CDN 검증은
격리 개발 tenant에서 수행하고 tenant/user residue zero를 확인한다.


## 복습 시청시간

모든 학원의 파일 업로드와 YouTube 링크 등록은 영상마다 `review_watch_limit_enabled`를 선택한다. 미지정 또는 false는 제한 없이 등록하며 true일 때만 복습에 한도를 적용한다. 수강생 전용·학원 공개 영상 모두 같은 선택을 제공한다. 파일 길이는 인코딩에서 확인한다. 제한을 선택한 YouTube 링크는 선생님이 원본 길이를 입력해야 저장된다. YouTube 집계는 학원 플레이어 안의 시청에 적용된다. 기존 영상은 저장된 개별 정책을 유지한다. 길이 확인이 필요한 제한 영상은 재생 진입 시 안내한다. 관리자가 준비된 영상에 제한을 켜면 학생 한 명의
자유 복습 허용량은 원본 길이의 1.4배가 된다. 60분 영상은 84분이다. 같은 테넌트에서
수강 경로와 기기가 달라도 영상과 학생이 같으면 누적량을 공유한다. 수업 대체 시청은
별도 정책을 따른다. 집계 이전 진도와 접속 기록은 누적시간에 소급 합산하지 않는다.

선생님은 YouTube 원본 길이를 영상 상세에서 정정할 수 있다. 기존 원장은 보존하며 다음 재생 판정부터 새 길이를 사용한다. 영상별 설정과 길이 변경은 `X-Expected-Updated-At`을 받아 편집 중 다른 사용자가 먼저 저장하면 409와 현재 수정 시각을 반환한다. 제한 중인 업로드 파일의 길이는 인코더가 관리한다.

학생 플레이어는 재생·정지·버퍼링 전환과 재생 중 주기 신호를 보낸다. 서버는 학생별
원장을 잠그고 순번을 검사해 재전송과 역순 요청을 처리한다. 신호 없이 종료된 구간은
최대 20초까지만 계산한다. 제한 영상 재접속 시 이전 재생 권한을 닫고 남은 시간을
확인한다. 업로드 영상의 재생목록과 조각은 현재 재생 권한을 확인하고 조각만 짧게
서명해 전달한다. 학생 사이트의 Pages Function은 이 서명으로 전용 R2 영상 객체를 읽고 Range 응답을 전달한다.
잔여 시간이 1ms라도 조각을 허용한 시점에는 그 조각의 저장소 요청에 최소 5초를 부여한다. 수강 권한 만료 시각과 15초 상한은 그대로 적용한다. 잔여 시간이 0이면 새 조각은 발급하지 않는다.
조각 요청마다 최초 학생·수강 또는 개별 권한과 철회 상태를 재검증한다. 재생 중에도 서버가 확인한 위치와 플레이어 버퍼 범위의 조각만 발급한다. 탐색은 인증된 준비 POST가 승인한 위치에서 재개한다. 재전송된 상태 신호는 같은 순번을 사용하고 원장에 두 번 합산하지 않는다.
이미 열린 보호 재생목록은 선생님이 제한을 꺼도 조각 서명을 유지한다. 꺼진 동안 탐색은 준비 여유분을 소모하지 않는다. 다시 켜면 기존 원장의 잔여 시간과 위치를 검사한다. 수강 권한 자체를 철회하면 기존 조각과 재생 신호가 차단되며, 개별 권한 재승인 후에는 새로 재생해야 한다.
이전 버전이 제한 해제 중에 발급한 서명 없는 조각 주소는 제한이 꺼져 있고 같은 영상의 수강 권한이 유효할 때만 사용할 수 있다. 제한을 다시 켠 뒤 옛 목록을 들고 있으면 플레이어의 다시 시도로 새 서명 목록을 받는다.

이전 학생 목록 `media/videos/student/?session=…`은 현재 학생 목록의 학원·차시·개별 권한 판정을 사용하며 허용된 항목의 메타데이터 배열을 반환한다. `hls_url`은 null이고 재생 권한은 학생 재생 POST에서 발급한다. 이전 목록이 관리자용 직렬화기로 재생 주소를 노출하던 경로를 폐기했다. 공개 차시 목록 조회는 수강 정보를 읽기만 하며 실제 재생 시작에서 필요한 등록을 처리한다.
인증된 재생 준비 POST가 현재 위치 앞 3초부터 뒤 16초에 걸친 조각을 30초간 허용한다.
기존 준비 위치 자체를 다시 요청하는 경우에는 유효한 승인을 그대로 반환한다. 그 밖에는 준비 여유분 부족으로 재시도 시간이 남아 있어도, 서버에 마지막으로 기록된 일시정지 위치에서 재개하고 기존 승인의 유효시간이 16초 이상 남아 있으면 이미 허용된 재생 구간을 재사용한다. 이 재요청은 준비 여유분을 소모하거나 승인 위치·만료 시각을 변경하지 않는다. 재생 기록이 없는 탐색, 다른 위치로의 이동, 만료가 임박한 승인은 기존 새 준비·30초 재시도 경로를 사용한다. 조각 경계 바로 앞의 짧은 버퍼나 만료 직전 승인을 재사용해 다음 조각이 429로 막히지 않도록 이 조건을 구분한다.
위치는 재생목록의 조각별 서명으로 확인한다. 같은 파일의 GET·HEAD·Range 재시도는 상태를 쓰지 않는다.
먼 위치에서 이어볼 때 네이티브 플레이어가 메타데이터를 읽을 수 있도록, 유효한 준비 또는 재생 신호가 있는 동안 영상의 처음 16초 안에 완전히 들어오는 조각도 허용한다. 16초 경계를 넘는 조각은 별도로 승인된 재생 위치에 속해야 한다. 이 읽기에는 시청시간을 차감하지 않는다.
준비 여유분은 학생·영상 단위로 공유하고 실제 재생으로 보충한다. 소진 후에도 30초에 한 번
빈 버퍼를 시작할 수 있다. 버퍼링·일시정지 POST는 직전 재생 위치에서 대기 중인 조각을 허용한다.
미리받기와 재생 준비는 시청시간을 차감하지 않는다. YouTube는 학원 플레이어 안에서 집계한다.

제한 활성화 전 발급한 권한은 기존 시청을 마칠 수 있도록 한 차례 시청 범위에서 갱신한다.
새로 제한 영상을 열 때에는 집계를 지원하는 학생 클라이언트가 필요하다. 이 정책 전환은
진행 중인 수업 대체 재생 토큰의 버전을 바꾸지 않는다.

테넌트 스태프는 영상 상세에서 누적시간·원본 대비 배율과 기준 도달 학생을 조회한다.
집계 이후 실제 기록이 있는 복습 학생을 포함한다. 저장 실패 시 학생은 다시 연결해
남은 시간부터 재생하고, 한도를 모두 쓰면 재접속으로 초기화할 수 없다.
검증은 `tests/test_direct_video_entitlement.py`의 복습 제한 시나리오를 사용한다.

## 학생 재생 정책·진도·댓글 일관성

- 활성 수강의 목록/재생 권한은 명시 차단을 먼저 적용하고, 교사 지정
  `is_override`를 출결 기본값보다 우선한다. 지정된 감독 시청도 완료 기준을
  만족하면 복습으로 전환한다. 목록은 미리 조회한 권한·진도·출결을 사용하며
  영상별 추가 조회를 만들지 않는다. 세션 소속·테넌트 검증, 비활성 수강의
  정확한 entitlement와 직접 접근의 별도 읽기 전용 경계는 유지한다.
- `block_speed_control`은 감독/복습 모드 기본값과 배속 override보다
  우선한다. 서버 정책은 최대 1배속과 배속 UI 비활성을 함께 반환한다.
  건너뛰기 차단·예산과 워터마크 제한을 완화하지 않는다.
- 학생 및 선택 자녀의 진도 저장은 `services/student_progress.py`에서
  영상/수강별 행 잠금과 유일 키를 이용해 병합한다. 지연·중복·재시청 요청은
  저장된 진도 최댓값과 완료 플래그를 내릴 수 없으며 `last_position`은
  뒤로 이동할 수 있다. 완료 임계값과 raw `completed=False` 표현은 유지한다.
  건너뛰기 사용량은 변경하지 않는다. 비활성 entitlement는 기존 잠금과
  재검증을 통과한 뒤 같은 병합을 사용하며 직접 접근은 DB 진도를 쓰지 않는다.
- 교사의 명시 진도 수정/초기화는 기존 staff 전용 경로를 사용한다.
  학생 병합을 모델 전체에 적용하거나 완료 마커를 새로 생성하지 않는다.
  다음 학생 저장은 초기화 후의 DB 상태를 기준으로 한다. 기존
  `proctored_completed_at`의 교사 관리 규칙은 변경하지 않는다.
- 댓글 GET은 삭제된 원문을 빈 내용의 placeholder로 반환하면서 그 아래의
  기존 살아 있는 답글을 보존한다. 학생 탈퇴 제외, 동일 테넌트/영상 범위,
  최상위 100개·답글 20개 제한은 유지한다. 삭제된 답글은 노출하지 않는다.
  삭제된 원문에 대한 신규 답글 POST는 400으로 거절하고 행/카운터를 쓰지 않는다.
  원문 행 잠금으로 삭제와 답글 생성을 직렬화하고 댓글 쓰기와 카운터 변경은
  같은 트랜잭션에서 처리한다. 작성된 내용의 물리 삭제나 하위 답글 연쇄 삭제는 없다.
- [학생 시청 UI 계약](https://github.com/guswls3028-art/academy-frontend/blob/main/docs/STUDENT-VIDEO-WATCH.md)은 삭제 placeholder 아래 답글 표시와 POST 실패 후 재조회/재시도를
  담당한다. backend 응답 필드와 기존 soft-delete 저장 구조는 유지한다.
- 회귀 검증: `tests/test_student_video_contract_regressions.py`와 기존
  student progress/session/direct/inactive entitlement 및 video access/security
  테스트. 실제 행 잠금의 동시성 검증은 PostgreSQL 환경에서 수행한다.

## 관리자 시청 기록 조회

관리자는 영상 상세의 시청 로그에서 누적 시간 목록을 확인하고 학생 상세의 활동으로
들어간다. 프런트 동선 정본은 frontend `docs/STUDENT-VIDEO-WATCH.md`다.
`review-watch/report/`는 기존 학생·영상별 원장을 그대로 읽으며 제한 OFF·직접 부여도
포함한다. `started_at`은 원장 집계 시작이며 최초 시청/최근 접속/세션 시작이 아니다.
임시 재생 스트림으로 과거 세션 시간을 재구성하지 않는다. 기존 원장/이벤트/설정은 보존한다.

`GET /api/v1/media/video-playback-events/`의 선택적 양의 정수 `student`는 수강 ID가
아닌 학생 ID를 받아 그 학생의 수강 이벤트만 조회한다. `risk/`와 `export/`도 동일한
video/student/range/enrollment 필터를 적용한다. 잘못된 학생 ID 형식은 400이며,
다른 tenant 학생/수강/영상 연결은 결과에서 제외한다. tenant staff 권한은 필수이며
학생·학부모는 접근할 수 없다. 직접 부여에는 수강 이벤트를 새로 만들지 않는다.
페이지네이션은 기존 공통 계약을 사용하고 기본 로그 화면은 위험점수 전체 집계를 호출하지 않는다.
CSV의 사용자 작성 문자열은 스프레드시트 수식으로 해석되지 않도록 리터럴로 내보낸다.
CSV는 UTF-8 BOM을 포함해 Excel에서 직접 열어도 한글 이름과 활동 내용이 유지되도록 한다.
기록 조회는 읽기 전용이며 오류 시 프런트는 명시적 재시도를 제공한다.

검증: `tests/test_video_watch_log_filters.py`의 학생 필터/list·risk·CSV 일치,
비정상 tenant 연결 차단, 잘못된 ID, 학생 권한 거부, OFF/직접 부여 누적 보존.

### 교직원 원본 다운로드

`POST /api/v1/media/videos/{id}/source-download/`는 같은 학원의 교직원에게만
보관 중인 업로드 원본을 확인한 뒤 5분 유효한 첨부 파일 주소를 발급한다.
외부 영상·업로드 대기 영상·사라진 원본은 발급하지 않는다. 주소는 감사 로그에 남기지 않는다.

원본이 보관되지 않은 경우, 교직원은 `GET/POST /api/v1/media/videos/{id}/playback-export/`에서
같은 학원의 재생 가능한 HLS 영상으로 MP4를 준비하고 다운로드할 수 있다. 영상과 음성을 재인코딩하지 않는다.
준비 상태를 확인하는 GET은 링크를 만들지 않으며, 완료 뒤 명시적으로 요청한 POST만 첨부 주소를 발급한다.
준비한 파일은 최대 24시간 사용할 수 있고, 주소는 최대 5분 유효하다.
