# 운영 대시보드 업무 집계

현재 학원의 owner/admin/staff/teacher가 대시보드·상단 알림에서 처리할 업무를
확인한다. `GET /api/v1/results/admin/teacher-dashboard-counts/`는 현재 학원에
한정한 전체 건수를 반환한다. 학생·학부모와 다른 학원 세션은 접근할 수 없다.

| 필드 | 집계 기준 |
|---|---|
| `qna_pending` | 게시 상태 질문 중 댓글이 없는 글. 플랫폼 문의, 삭제된 학생 작성 글 제외 |
| `counsel_pending` | 게시 상태 상담 중 댓글이 없는 글. 교직원 작성 상담·교사 내부 메모, 플랫폼 문의, 삭제된 학생 작성 글 제외 |
| `submission_pending` | 제출 처리함과 동일한 pending 상태. 과제 제외, 상세 목록의 200건 제한 없이 전체 집계 |
| `video_failed` | 삭제되지 않은 영상 중 최근 30일 이내 갱신된 인코딩 실패 |

미답변은 기존 정책인 **댓글 0개**를 유지한다. 댓글 작성자의 역할에 따라
답변 완료를 새로 판단하지 않는다. 글 내용과 제출 상세는 집계 응답에 포함하지
않는다. 게시글 조건은 community selector, 제출 상태는 submissions repository가
소유한다. GET 조회는 데이터를 변경하지 않는다.

이전 클라이언트는 질문·상담 첫 100개와 제출 첫 200개를 읽어 건수를 추산해
오래된 대기 업무를 누락했다. 집계 필드를 기존 응답에 추가하며 기존 상세 API,
댓글·제출 데이터와 `video_failed` 계약은 보존한다. 데이터 이전은 없다.
백엔드를 먼저 배포하고 확장 응답을 사용하는 화면을 승격한다.

프런트는 누락·음수·소수 등 비정상 집계나 조회 실패를 0건으로 확정하지 않는다.
정상 항목은 유지하고 실패 항목·전체 합계에 확인 필요와 재시도를 제공한다.
새로고침과 재시도는 서버 집계를 다시 읽는다. UI 동작 정본은 프런트
`docs/TEACHER-WORKSPACE-OPERATIONS.md`이다.

검증: `tests/test_operational_dashboard_counts.py`의 실제 JWT API 요청으로
최근 답변 100개 뒤 미답변 105개, 제출 205개, 답변 후 재조회, 보관·임시 글·내부
메모·삭제 학생 제외와 학원/역할 격리를 확인한다. 프런트
`e2e/admin/operational-count-totals.mock.spec.ts`는 PC·390px 정상·전체/부분 실패,
재시도·reload·불필요한 상세 요청 제거를 확인한다. 제출 상세 목록 200건 이후
탐색과 답변 완료 정의의 변경은 이 집계 수정에 포함되지 않는다.
