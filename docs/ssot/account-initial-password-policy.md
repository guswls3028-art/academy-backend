# 계정 초기 비밀번호 정책 SSOT

2026-10-02 명시 선택 계약. 학생·학부모 신규 계정, 직원 등록·가입 승인·복원과
Excel 등록의 초기 비밀번호 정책은 이 문서와 `apps/core/services/initial_password_policy.py`가 소유한다.
등록 화면의 상호작용은 frontend `docs/ACCOUNT-CREDENTIAL-FLOWS.md`가 소유한다.

## 설정과 우선순위

- `Tenant.account_password_policy`는 해당 학원의 학생·학부모 설정만 보관한다.
  미설정 역할은 `null`로 조회한다. 빈 설정에 전화번호 또는 랜덤 방식을 자동 대입하지 않는다.
- 방식은 `fixed`(직접 입력), `phone_last4`(본인 번호 뒤 4자리), `random`(6자리 숫자) 세 가지다.
- 직원은 학원 설정에서 역할별 기본 방식을 명시 저장한다. 한 학원의 선택은
  다른 학원, 공통 코드 기본값 또는 신규 학원에 복사하지 않는다.
- 등록의 최종 확인창은 방식이 선택되지 않은 상태로 열린다. 저장된 학원 기본값은
  참고 정보로 표시하며 선택/동의를 대신하지 않는다. 학생·학부모 방식을 명시 선택하고
  유효한 입력을 확인한 다음에만 등록한다. 취소·Escape·연속 Enter는 등록하지 않는다.
- 확인창의 선택이 등록 요청에 우선한다. `fixed`는 원문 4자 이상을 명시 입력하며
  공백을 제거하지 않는다. `phone_last4`는 각 역할의 검증된 본인 번호만 사용한다.
  학생 번호가 없거나 학부모 번호와 같으면 다른 방식을 선택하도록 안내한다.
  전화번호 부족을 랜덤 방식으로 바꾸는 묵시적 대체는 금지한다.
- `random`은 명시 선택한 역할에 서버에서 6자리 값을 생성한다. 생성 결과는 실제
  로그인 hash와 안내 값이 일치해야 한다. 임시 값·설명 문구를 비밀번호 변수로 쓰지 않는다.
- 기존 클라이언트의 명시 비밀번호와 기존에 직원이 저장한 역할 설정은 호환된다.
  둘 다 없으면 400 또는 행 단위 복구 가능한 실패를 반환하며 계정 그래프를 남기지 않는다.
  가입자가 선택한 학생 비밀번호와 학부모 방식/직접 입력값은 승인 대기 중에도
  보존한다. 직원 승인·학원 설정 변경으로 덮어쓰지 않는다. 과거 신청에 학부모
  선택이 없으면 직원이 신규 학부모 방식을 지정한다. 기존 사용 가능한 학부모 계정은 유지한다.

## 저장·권한·기존 데이터 보존

- `GET/PATCH /students/account-password-settings/`는 현재 학원 직원만 허용한다.
  다른 학원 지정 파라미터와 알 수 없는 필드는 거부한다.
- PATCH는 최신 Tenant 행을 잠그고 요청한 키만 변경한다. 다른 역할의 설정,
  변경하지 않은 암호문, 기타 기존 정책 키를 보존하며 stale 객체로 덮어쓰지 않는다.
  직접 입력 기본값은 tenant/role 문맥에 묶인 암호문으로 저장한다.
- 설정 변경은 이후 신규 계정에만 적용한다. 기존 User hash, 세션 및 기존 학부모
  계정은 바꾸지 않는다. 새 자녀 연결에서 입력한 학부모 초기 값도 기존 계정을 초기화하지 않는다.
- 사용 가능한 기존 학부모를 재사용할 때는 초기 설정 유무를 요구하지 않는다.
  새 계정/비밀번호가 없는 계정에만 선택한 초기 정책을 적용한다.
- 승인 대기 학부모 직접 입력값은 `signup-parent:{tenant_id}` 문맥의 암호문으로만
  보관한다. 조회 API는 선택 여부만 공개한다. 승인/복구 승인/거절 시 학생·학부모
  신청 암호문을 지우며, 문맥 불일치·손상은 계정을 만들지 않고 복구 가능한 오류로 반환한다.
  students0021은 빈 기본값의 필드 추가만 수행하며 기존 신청/계정/설정을 변환하지 않는다.
- 역할 설정을 일괄 seed하는 migration은 만들지 않는다. 이동휘의 요청은 정확한
  tenant10/code movementhui의 미설정 역할에만 운영 설정으로 반영한다.
  이미 저장된 값은 읽어 확인하고 보존한다. 코드에 tenant 이름에 따른 분기를 넣지 않는다.

## 안내와 검증

- 첫 실제 수강과 재안내는 현재 hash 또는 유효한 로그인용 임시 값만 발송한다.
  기존 비밀번호·세션 유지, 계정 안내 암호문, 승인된 채널·템플릿과 outbox 계약은
  `docs/domain/parent-account.md`, `docs/domain/account-recovery.md`,
  `docs/ssot/messaging-policy.md`를 따른다.
- 회귀 검증은 미설정 상태/명시 선택 성공, 본인 번호 부족→다른 선택으로 성공,
  tenantA 변경이 tenantB에 영향0, 부분 PATCH/stale 보존, 기존 학부모 hash 보존,
  실제 JWT 로그인·저장/재조회·후속 알림톡을 포함한다. 390px/데스크톱에서도
  최종 선택·입력·취소·오류 복구가 완료되어야 한다.
- 이전 전역 `phone_last4` 기본값과 번호 부족 시 랜덤 대체를 폐기한다.
  이유는 학원의 명시 선택을 대신하고 다른 테넌트의 신규 계정 정책을 바꾸기 때문이다.
  기존 계정이나 정책 데이터의 자동 변환·삭제는 없다.
