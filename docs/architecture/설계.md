```

                    │     ├── academy-v1-ai-queue           → AI Worker CPU ASG
                    │     └── academy-v1-messaging-queue    → Messaging Worker ASG
```

## 3. 워커 실행 경로

- **Messaging**: `academy-v1-messaging-queue` → `academy-v1-messaging-worker-asg`(SSOT min/desired=1 warm baseline, SQS alarm StepScaling up to max). 계정복구/알림톡은 사용자 대기 경로이므로 cold-start 없이 처리한다. 코드 배포는 ASG instance refresh로 반영한다.
- **AI**: `academy-v1-ai-queue` → `academy-v1-ai-worker-asg`는 SSOT min/desired=1 warm baseline을 유지한다. CloudWatch AWS/SQS alarms(`ai-worker-queue-high`, `ai-worker-queue-age-high`) + API wake-up이 burst를 scale-out하고, 워커의 live SQS depth 확인이 유휴 시 desired=1까지만 내린다. `ai-worker-queue-low`는 관측용이다.
- **Tools**: `academy-v1-tools-queue` → `academy-v1-tools-worker-asg`는 Excel/PPT/PDF 첫 요청 지연을 막기 위해 SSOT min/desired=1 warm baseline을 유지하고 SQS alarm StepScaling으로 max까지 확장한다.
- **Video**: AWS Batch 전용. daemon/SQS/Video ASG 경로는 2026-05-10 폐기.
- **배포**: backend `main` push → GitHub Actions worker refresh. 인프라 정합화는 `scripts/v1/deploy.ps1`.

AI 유휴 축소의 반환값은 기본 용량 도달 여부가 아니라 실제 ASG 축소 요청 여부다.
현재 desired가 설정된 warm baseline 이하이면 용량 변경 없이 `False`를 반환하여
워커가 heartbeat와 SQS 수신을 계속한다. baseline 위의 burst 용량을 실제로 내린
경우에만 `True`를 반환하고 워커가 정상 종료한다. 큐에 작업이 남거나 조회·축소가
실패하면 기존처럼 수신을 계속하며, 작업 claim·ACK나 tenant 데이터는 변경하지 않는다.
회귀 검증은 `test_ai_worker_capacity_control.py`와 `test_ai_worker_idle_scale_in.py`에서
기본 용량의 다음 poll 및 3→1 축소 후 종료를 실제 어댑터와 워커 루프로 확인한다.
운영 확인에서는 유휴 관측 구간에도 기본 용량 워커의 heartbeat가 이어지고
`AI_IDLE_SCALE_IN_REQUESTED`로 인한 주기적 재시작이 없는지 구분한다.

## 4. 비용 (3~4 TB 가정, 월)

| 구분 | 낮음 | 높음 |
|------|------|------|
| Video Batch compute | $5 | $20 |
| EBS | $3 | $8 |
| R2 저장 3~4 TB | 약 $45 | 약 $60 |
| **합계** | **약 $53** | **약 $93** |

R2 + Cloudflare CDN → egress GB 과금 없음. 시청 증가 = R2 Class B 요청만.
